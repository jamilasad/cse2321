Segment 2 Segment 3

Arrays & Linked Lists

?Array vs linked list — which is better?
Neither. It depends on what you do most. That answer alone scores marks, because the question is a trap for anyone who memorised one side.

Array: instant access to any position (a[i] is one step, because the memory is contiguous). But inserting in the middle means shifting everything after it — O(n). Fixed size.
Linked list: inserting is O(1) once you are standing there. But getting there means walking from the head — O(n). No jumping. And every node costs an extra pointer of memory.
?What about inserting in the middle? Cover all the scenarios.
This was the explicit follow-up in the transcript. Answer it as three cases:

1. You already have a pointer to the node. Linked list wins outright — O(1) rewiring vs O(n) shifting.
2. You must search for the position first. Both are O(n). The array often wins in practice because contiguous memory is far friendlier to the CPU cache.
3. The data is sorted and you can binary search. Array wins clearly — O(log n) to find plus O(n) to shift, versus O(n) just to walk the list.

Say the last line out loud: "so the linked list only wins when I already hold the position."

Segment 4 Segment 5

Stacks, Recursion & Queues

?Stack vs queue — the difference, and when you use each
Stack is LIFO — last in, first out. Insert and remove at one end only, called the top. Use it when the most recent thing matters: undo, function calls, matching brackets, the browser back button.

Queue is FIFO — first in, first out. Insert at the rear, remove from the front. Use it when order of arrival matters: print jobs, request queues, spreading level by level through a graph.

Memory aid: stack is a pile of plates, queue is a line at the bus stop.
?What is a priority queue? How is it different from a queue?
A normal queue serves in arrival order. A priority queue serves in importance order — whoever is most urgent goes next, no matter when they arrived.

The picture: a hospital emergency room. Not first come first served. Most serious first.

The follow-up: "how would you build it?" A sorted list makes insert slow. An unsorted list makes extract slow. A heap makes both O(log n) — which is exactly why the heap exists.
?Reverse a string using recursion
They want to see whether you can find a base case and shrink the problem.

reverse(s):
  if s is empty or has one character → return s
  return reverse(s without first char) + first char

Give the complexity before they ask: O(n) calls and O(n) stack space. If they ask for it without recursion, use two pointers swapping from both ends — O(n) time, O(1) space.

Segment 6

Sorting

?Which sorting algorithm is best?
Never answer with one name. Answer "it depends on the data" and give three cases:

Nearly sorted → insertion sort. O(n) when the data is almost in order.
Small range of integers (ages 1–100) → counting sort or radix sort. They do not compare at all, so they beat the O(n log n) barrier.
Large data, tight memory, worst case must be guaranteed → heapsort. In-place and O(n log n) guaranteed.

This is Question 3(b) on the Spring 2026 final paper, almost word for word.
?Compare quick sort and merge sort (Semester 4)
Merge sort: always O(n log n), stable, but needs O(n) extra memory for merging.
Quick sort: O(n log n) on average and usually faster in practice (better cache behaviour, sorts in place), but O(n²) in the worst case and not stable. A random pivot makes the worst case very unlikely.

The one-liner: "quick sort is usually faster; merge sort is the one you pick when you need a guarantee or stability."

Taught in Semester 4
?Which strategy does merge sort use? Explain divide and conquer. (Semester 4)
Divide and conquer, in three steps: divide the problem into smaller pieces of the same kind, conquer each piece (usually by recursion), combine the answers.

Merge sort: split the array in half, sort each half recursively, then merge the two sorted halves. The merge is the clever part — walking two sorted lists with two pointers, always taking the smaller front element.

Taught in Semester 4
?Name one greedy algorithm and explain it (Semester 4)
Pick one you can explain fully. Activity selection is the cleanest:

Given activities with start and finish times, choose the most that do not overlap. Greedy choice: always take the activity that finishes earliest among those still compatible. Sort by finish time and sweep once.

Then say why greedy is risky: it only works when the problem has the greedy-choice property. Fractional knapsack works greedily; 0/1 knapsack does not, and that failure is exactly what motivates dynamic programming.

Segment 8

Trees & Heaps

?What is a heap? What is heapify?
A heap is a complete binary tree where every parent is better than its children — smaller in a min-heap, larger in a max-heap. It is stored in a plain array with no pointers: the children of index i sit at 2i and 2i+1.

Heapify is the repair operation. After removing the root, put the last element on top and let it sink down, swapping with its better child until the heap rule holds again — O(log n).

The trap they love: building a heap from n elements is O(n), not O(n log n).
?Perfect vs full vs complete binary tree
Full: every node has 0 or 2 children. Never exactly one.
Complete: every level filled except possibly the last, and the last fills left to right. This is the shape a heap must have.
Perfect: every level completely filled, all leaves at the same depth. A perfect tree is both full and complete.

Win the question with: "a heap must be complete, which is why it can live in an array with no gaps."
?How does a BST work? Why is search sometimes O(n)?
A binary search tree keeps everything smaller than a node on its left and everything larger on its right. To search, compare once and throw away half the tree — O(height).

The catch: height is only log n if the tree is balanced. Insert 1, 2, 3, 4, 5 in order and every node goes right — you have built a linked list wearing a tree costume. Now search is O(n).

That failure is exactly why AVL and red-black trees exist. Saying that shows you understand the reason for the next topic.
?Name the tree traversals and say what each is for
Inorder (left, node, right) — on a BST this gives the values in sorted order. That is the one they want.
Preorder (node, left, right) — copying or serialising a tree.
Postorder (left, right, node) — deleting a tree, or evaluating an expression tree.
Level order — level by level using a queue. This is BFS on a tree.

The transcript's follow-up: "which graph algorithm can we use?" Answer: the first three are DFS, level order is BFS. A tree is just a graph with no cycles.
?Find the 3 smallest elements in a large array — then optimise it
Asked in the transcript including the "now optimise" follow-up. Three steps:

1. Obvious: sort and take the first 3 — O(n log n).
2. Better: keep a max-heap of size 3. Walk the array once; if a number is smaller than the heap's top, replace it. O(n log 3) = O(n), using only 3 slots of memory regardless of array size.
3. Say the tradeoff: sorting also gives you everything else in order; the heap gives only the 3. If 3 is all you need, do not pay for the rest.

That is Question 4(d) on your final paper with different numbers.
?Can you turn a linked list into a BST?
The interviewer skipped this one as ambiguous — but it is worth knowing, and the ambiguity is the answer.

If the list is sorted: take the middle node as the root, recurse on the left half and the right half. That gives a balanced BST in O(n).
If it is unsorted: you must insert nodes one at a time — O(n log n) at best, O(n²) if they arrive in sorted order and the tree degenerates.

The good answer starts by asking: "is the list sorted?" That is what the interviewer was actually testing.

Semester 4 · Algorithms

Graphs

?Graph traversal — BFS and DFS
BFS uses a queue and explores level by level. It finds the shortest path in an unweighted graph.
DFS uses a stack (or recursion) and goes as deep as possible before backtracking. It is used for cycle detection, topological sort and finding connected components.

Both are O(V + E) with an adjacency list. The connection to say out loud: "level-order traversal of a tree is BFS — a tree is just a graph with no cycles."
?What is a spanning tree? A minimum spanning tree?
A spanning tree connects all V vertices of a graph using exactly V−1 edges and no cycles.
A minimum spanning tree is the spanning tree with the smallest total edge weight.

Two algorithms: Kruskal sorts all edges and adds the cheapest that does not create a cycle (using union-find). Prim grows one tree outward, always taking the cheapest edge leaving it (using a priority queue).

Real use: laying cable or road to connect every town at the lowest total cost.
