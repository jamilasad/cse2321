⚠ Why we move from the RIGHT, not the left

If you moved left-to-right you would overwrite the next element before copying it. Starting from the last element and working backwards, every cell you write into has already been copied to safety.

Get this backwards in the exam and the algorithm is wrong even though it looks right.

Insert at the K-th position
INSERT(LA, N, K, ITEM). LA is a linear array with N elements, K a positive integer with K ≤ N + 1. This algorithm inserts ITEM into the Kth position.
Step 1. [Initialize counter] Set J := N. Step 2. Repeat Steps 3 and 4 while J ≥ K: Step 3. [Move Jth element downward] Set LA[J + 1] := LA[J]. Step 4. [Decrease counter] Set J := J − 1. [End of Step 2 loop] Step 5. [Insert element] Set LA[K] := ITEM. Step 6. [Reset N] Set N := N + 1. Step 7. Exit. 
// 0-based C++. K is the position we want ITEM to land on.
void insertAt(int a[], int &n, int k, int item) {
    // walk BACKWARDS so nothing is overwritten before it is copied
    for (int j = n - 1; j >= k; j--)
        a[j + 1] = a[j];

    a[k] = item;
    n++;                      // the array is one longer now
}
bestO(1)averageO(n)worstO(n)spaceO(1)

The complexity — the second half of the exam question

Best case: insert at the end (K = N+1). Nothing moves → O(1).
Worst case: insert at the front (K = 1). All N elements move → O(n).
Average case: about n/2 elements move → still O(n).

Answer to write: O(n). Say the worst case is insertion at the beginning and give the reason — the shifting.

Delete the K-th element
DELETE(LA, N, K, ITEM). LA is a linear array with N elements and K a positive integer with K ≤ N. This algorithm deletes the Kth element.
Step 1. Set ITEM := LA[K]. Step 2. Repeat for J = K to N − 1: [Move J+1st element upward] Set LA[J] := LA[J + 1]. [End of loop] Step 3. [Reset N] Set N := N − 1. Step 4. Exit. 
// 0-based C++. Returns the value that was removed.
int deleteAt(int a[], int &n, int k) {
    int item = a[k];          // save it before it is overwritten

    // walk FORWARDS: each cell we write has already been read
    for (int j = k; j < n - 1; j++)
        a[j] = a[j + 1];

    n--;
    return item;
}
bestO(1)averageO(n)worstO(n)spaceO(1)

Notice the direction flipped

Insert walks backwards (J = N down to K) so it never overwrites.
Delete walks forwards (J = K up to N−1) for exactly the same reason — each cell it writes into has already been read.

Same complexity either way: O(n). Deleting the last element is free; deleting the first moves everything.

The array's real weakness

The very thing that makes reading fast — elements packed side by side with no gaps — is what makes inserting and deleting slow.

You cannot have both. Segment 3 gives up the fast reading to get fast insertion. That is the whole reason the linked list exists.

Quick check
You delete the first element of a 1,000-element array. How many elements move?
999. Every element from position 2 to position 1,000 slides one place left — that is 999 moves. The deleted one does not move; it is overwritten. This is the worst case, and it is why deletion is O(n).

Linear search
LINEAR(DATA, N, ITEM, LOC). Here DATA is a linear array with N elements, and ITEM is the value we are looking for. This algorithm finds the location LOC of ITEM in DATA, or sets LOC = 0 if the search is unsuccessful.
Step 1. [Initialize counter] Set LOC := 1. Step 2. Repeat while LOC ≤ N: If ITEM = DATA[LOC], then: Write: LOC. Exit. Set LOC := LOC + 1. [End of loop] Step 3. [Unsuccessful] Set LOC := 0. Step 4. Exit. 
// returns the position of key, or -1 if it is not there
int linearSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key) return i;
    return -1;
}

int main() {
    int a[6] = {30, 50, 20, 70, 40, 90};
    int loc = linearSearch(a, 6, 70);
    cout << loc;              // prints 3
}
bestO(1)averageO(n)worstO(n)spaceO(1)

Dig deeper

?The sentinel trick — how to remove one test per round

Count the work in the loop above. Every single round it checks two things:

1. Have I run off the end of the array?  (i < n)
2. Is this the one I want?  (a[i] == key)

The first test is only there to stop the loop from walking out of the array. So here is the trick: put the value you are looking for into one spare cell at the end — DATA[N+1]. That copy is called the sentinel (a guard).

Now the loop cannot run off the end, because it is guaranteed to find a match — at worst it finds the sentinel. So test 1 can be deleted, and only test 2 stays.

Afterwards you ask one question: did I stop on the sentinel? If LOC came back as N+1, the real array never had ITEM, so set LOC := 0.

Turn on the "Sentinel" button under the simulator above and watch the purple cell appear at the end.

Linear search · sentinel version
LINEAR(DATA, N, ITEM, LOC). Same job as before, but DATA must have room for one extra cell at the end.
Step 1. [Insert ITEM at the end of DATA] Set DATA[N + 1] := ITEM. Step 2. [Initialize counter] Set LOC := 1. Step 3. [Search for ITEM] Repeat while DATA[LOC] ≠ ITEM: Set LOC := LOC + 1. [End of loop] Step 4. [Successful?] If LOC = N + 1, then: Set LOC := 0. Step 5. Exit. 
// the array needs ONE spare cell: size n + 1
int linearSentinel(int a[], int n, int key) {
    a[n] = key;                  // the sentinel
    int i = 0;
    while (a[i] != key) i++;    // only ONE test now
    return (i == n) ? -1 : i;   // stopped on the sentinel?
}

int main() {
    int a[7] = {30, 50, 20, 70, 40, 90};  // 6 values, 1 spare
    cout << linearSentinel(a, 6, 70);           // prints 3
}
worstO(n)tests per round1extra space1 cell

So is it worth it? The complexity does not change — it is still O(n). You have only halved the work inside one round. It is a classic example of the time–space trade-off from Segment 1: you paid one extra cell of memory to save one test per round.

In the exam: the plain version is what you should write unless the question asks for the sentinel by name. And notice the danger — if you forget the spare cell, a[n] = key writes outside the array.

The idea: walk along the list comparing neighbours. If they are in the wrong order, swap. The biggest element "bubbles" to the end. Repeat.

The answer you write in the exam

Bubble sort
BUBBLE(DATA, N). DATA is an array with N elements. This algorithm sorts the elements of DATA into ascending order.
Step 1. Repeat Steps 2 and 3 for PASS = 1 to N − 1: Step 2. Set PTR := 1.  [Initialize pass pointer] Step 3. Repeat while PTR ≤ N − PASS: If DATA[PTR] > DATA[PTR + 1], then: Interchange DATA[PTR] and DATA[PTR + 1]. [End of If structure] Set PTR := PTR + 1. [End of inner loop] [End of Step 1 outer loop] Step 4. Exit. 
// plain bubble sort — always O(n^2)
void bubbleSort(int a[], int n) {
    for (int pass = 0; pass < n - 1; pass++)
        for (int j = 0; j < n - 1 - pass; j++)
            if (a[j] > a[j + 1])
                swap(a[j], a[j + 1]);
}
bestO(n) *averageO(n²)worstO(n²)spaceO(1)

How to count C without simulating

Pass 1 makes n−1 comparisons, pass 2 makes n−2, and so on down to 1. So

C = (n−1) + (n−2) + … + 2 + 1 = n(n−1)/2

For CANDLE, n = 6 → C = 6×5/2 = 15. For STRUCTURES, n = 10 → C = 10×9/2 = 45.

C never depends on the letters — only on how many there are. D does: it is the number of pairs that started out in the wrong order.

Dig deeper

?Modify bubble sort to stop early — Spring 2024 Q2(c) [OR]
"Modify the bubble sort algorithm so that it will stop early if it detects that the list is already sorted."

Add a flag. If a whole pass makes no interchange, the list must already be sorted, so stop.

1. Repeat Steps 2 to 5 for PASS = 1 to N − 1:
2.      Set FLAG := 0.
3.      Repeat for J = 1 to N − PASS:
            If DATA[J] > DATA[J+1], then:
                Interchange DATA[J] and DATA[J+1]. Set FLAG := 1.
            [End of If structure]
      [End of loop]
4.      If FLAG = 0, then: Exit.
5.      [End of If structure]
  [End of Step 1 loop]
6. Exit.

What it changes: the best case becomes O(n) — one clean pass over an already-sorted list. Worst and average stay O(n²).

⚠ Without this flag, bubble sort has no O(n) best case at all. If a question says bubble sort is O(n) at best, it means this version.
?What exactly counts as an "interchange"?
One swap of two neighbouring elements. Not the three assignments inside it, and not a comparison that decided not to swap.

D equals the number of inversions in the input — the count of pairs that begin in the wrong relative order. That is why D changes with the word while C does not.

For CANDLE the inversions are C>A, N>D, N>L, N>E, L>E — five, which is exactly the D you get by simulating.
?Is bubble sort ever actually used?
Almost never in real code. O(n²) is hopeless past a few thousand elements, and std::sort is O(n log n) and already written.

It survives in teaching for two good reasons: it is the easiest sort to trace by hand, and it shows the invariant idea clearly — after pass K, the last K elements are guaranteed to be in their final places.

In your exam it is worth ~4 marks. In your job it is worth knowing why not to use it.

Binary search — building it from scratch

⏱ 16 min

Start with something you have done a thousand times

📖 Looking up a word in a dictionary

You want "structure". Do you start at page 1 and read every word?

Of course not. You open the dictionary somewhere in the middle, see you have landed on "M", and you know instantly that "structure" is in the right half. So you throw away the entire left half — hundreds of pages — without reading a single word of it.

Then you do it again. And again.

Why this works and reading page-by-page does not

Because the dictionary is sorted. One look in the middle tells you which half to abandon.

That is binary search, complete. Everything below is just writing it down carefully.

Why is it O(log n)? Count the halvings

Every look throws away half of what is left. Watch how quickly that empties the array.

That is exactly what a logarithm counts

"How many times can I halve n before reaching 1?" — you met this in Segment 1 as the paper-folding picture.

That count is log₂ n. So binary search is O(log n), and that is why a million elements needs only about 20 looks.

The comparison the exam wants — Spring 2023 Q2(d)

"What is the main (i) advantage and (ii) disadvantage of the Binary Search algorithm over the Linear Search algorithm?"

Advantage: far faster — O(log n) against O(n). On 1,000,000 elements, about 20 comparisons instead of a million.
Disadvantage: the array must be sorted first. If it is not, sorting costs O(n log n) — more than one linear search would have cost. It also needs random access, so it cannot be used on a linked list.

?Insert ITEM at the Kth position — Spring 2025 & Spring 2024, Q2(a) [2–2.5 marks]
"Write an algorithm to insert an element ITEM to the Kth position of a linear array LA. What is the time complexity of this algorithm?"

Algorithm: INSERT(LA, N, K, ITEM). LA is a linear array with N elements and K is a positive integer with K ≤ N + 1. This algorithm inserts ITEM into the Kth position of LA.

Step 1. [Initialize counter] Set J := N.
Step 2. Repeat Steps 3 and 4 while J ≥ K:
Step 3.      [Move Jth element downward] Set LA[J + 1] := LA[J].
Step 4.      [Decrease counter] Set J := J − 1.
  [End of Step 2 loop]
Step 5. [Insert element] Set LA[K] := ITEM.
Step 6. [Reset N] Set N := N + 1.
Step 7. Exit.

Time complexity: O(n). In the worst case (K = 1) all N elements must shift one place right; on average about n/2 do. Only inserting at the very end is O(1).

⚠ Two marks lost every year: looping forwards instead of backwards (which overwrites data), and forgetting Set N := N + 1.

?Binary search — advantage and disadvantage — Spring 2023, Q2(d) [1 mark]
"What is the main i) advantage and ii) disadvantage of the Binary Search algorithm over the Linear Search algorithm?"

Interview

What they ask about arrays

?Why is inserting into an array O(n) when reading is O(1)?
Because reading calculates an address, but inserting has to preserve the packing.

"Elements sit in successive locations with no gaps — that is what makes the address formula work. To open a slot in the middle, every element after it must shift one place right. In the worst case, inserting at the front, that is all n of them."

Then earn the follow-up: "which is exactly the trade a linked list reverses — O(1) insert once you hold the node, but O(n) to reach it."
?When would you use bubble sort?
Honestly: never in production. Say so — pretending otherwise reads badly.

"It is O(n²), so it is unusable past a few thousand elements, and every language ships an O(n log n) sort. I would use std::sort."

Then show you know why it is still taught: "it is the clearest sort to trace by hand, and with an early-exit flag it detects an already-sorted list in one O(n) pass — which is the one case where it beats quicksort."
?You have an unsorted array and one lookup to do. Sort it first?
No. A single linear search is O(n). Sorting first costs O(n log n) and then O(log n) to search — strictly worse for one lookup.

The real answer is "it depends on how many lookups": sorting pays for itself once you are doing many searches, because the O(n log n) is a one-off and every search afterwards is O(log n) instead of O(n).

That is a genuine engineering trade, and saying it out loud is what they are listening for.
?What does the sentinel trick actually save?
One comparison per iteration — the bounds check.

Without it every round asks two questions: am I past the end? and is this the item? Putting the item in the spare cell guarantees the loop terminates, so only the second question remains.

It does not change the complexity — still O(n). It halves the constant. Being clear that a constant-factor win is not a complexity win is exactly the distinction interviewers probe for.
