Where we are

Three classes of arrays: one address formula, seven operations, two dimensions.

A string is the fourth — and it is not a new structure at all. It is a linear array whose elements happen to be characters, with w = 1. Everything you already know still applies.

Section 1

A string is a character array

⏱ 7 min

Definition

A string is a finite sequence of characters taken from some alphabet — letters, digits, spaces, punctuation.

In memory it is stored exactly like the arrays of Class 1: successive locations, one byte each (w = 1 for a char), reached by the same formula.

Type a word and watch it laid out in memory. Notice the red cell at the end.

S =

The invisible last cell

C and C++ mark the end of a string with a hidden character, '\0' — the null terminator. So char s[] = "HELLO"; takes 6 bytes, not 5.

The classic array bug

char s[5] = "HELLO"; has no room for the terminator. The program will read past the end looking for one — the exact Class 1 out-of-bounds problem.

The C++ answer

string s = "HELLO"; manages its own memory and its own length. Use this. Section 6 covers everything it can do.

The point of the whole class

A string is an array. Nothing about the machine changes.

What changes is the vocabulary. The exam will not ask you to compute an address here — it will ask you what a terminal substring is, or to count comparisons in pattern matching. That vocabulary is the rest of this class.

Definition — straight from the textbook

The number of characters in a string is called its length. We write LENGTH(string).

Concatenation — S1 ‖ S2

⏱ 5 min

Definition

Let S1 and S2 be strings. The concatenation of S1 and S2, written S1 ‖ S2, is the string consisting of the characters of S1 followed by the characters of S2.

Two examples from the lecture. Look carefully at the difference.

S1 = ‖ S2 =

The rule that follows from it

LENGTH(S1 ‖ S2) = LENGTH(S1) + LENGTH(S2)

Nothing is added and nothing is lost — so if you want a space between two words, the space has to already be in one of them. That is the whole difference between the first two buttons above.

timeO(n + m) spaceO(n + m)

Every character of both strings has to be copied into the new one — so joining is not free. Building a long string by result = result + ch inside a loop copies the whole thing every round: that is the O(n²) trap you met in Segment 1.

Section 4 · learn this word for word

Substrings — S = X ‖ Y ‖ Z

⏱ 14 min

Definition — this is the exam wording

A string Y is called a substring of a string S if there exist strings X and Z such that

S = X ‖ Y ‖ Z If X is an empty string, then Y is called an initial substring of S.
If Z is an empty string, then Y is called a terminal substring of S.

Read it once more slowly. It is saying something very simple: cut S into three pieces. The middle piece is the substring. If there is nothing before it, it is initial. If there is nothing after it, it is terminal.

Drag the two sliders to choose Y and watch X, Z and the verdict change.

S =

X — before

Y — the substring

Z — after

Initial → starts at the start

X is empty, so Y begins at the very first character.
"TO BE OR" is an initial substring of "TO BE OR NOT TO BE".

Terminal → ends at the end

Z is empty, so Y runs to the very last character.
"NOT TO BE" is a terminal substring of "TO BE OR NOT TO BE".

Both at once

If X and Z are empty then Y is the whole of S. Every string is both an initial and a terminal substring of itself.

⚠ The rule the exam likes to test

If Y is a substring of S, then LENGTH(Y) cannot exceed LENGTH(S).

Obvious once you see the definition: S is made of X, Y and Z joined together, so Y is only a part of it. It can be equal, never longer.

Watch out for the word consecutive. "TO OR" is not a substring of "TO BE OR NOT TO BE" — you cannot skip characters. A substring is one unbroken run, exactly like the "successive memory locations" from Class 1.

Quick check
Let S = "THE END". Which of these is a terminal substring of S?
"END". Take X = "THE " and Z = "". Because Z is empty, Y is a terminal substring.

"THE" is an initial substring (X is empty instead). "HE E" is an ordinary substring — both X and Z have characters in them.

Dig deeper

?How many substrings does a string of length n have?
Choose a start and an end: n(n+1)/2 non-empty substrings, counting duplicates as separate choices.

For "ABCD" (n = 4) that is 4×5/2 = 10: A, AB, ABC, ABCD, B, BC, BCD, C, CD, D.

There are exactly n initial substrings and exactly n terminal ones — one for each length from 1 to n.
?Substring, subsequence, prefix, suffix — what is the difference?
Substring — consecutive characters. "BE OR" from "TO BE OR NOT". ✓
Subsequence — in order, but gaps allowed. "TOOT" is a subsequence of "TO BE OR NOT" but not a substring.

In English-language textbooks and on LeetCode you will meet prefix and suffix: a prefix is exactly an initial substring, and a suffix is exactly a terminal substring. Same idea, different word — know both, because your paper uses one set and the internet uses the other.

    string s = "Kazi Nazrul";

    cout << s.length();            // 11   — spaces count
    cout << s.substr(5, 6);         // Nazrul
    cout << s.substr(5);            // Nazrul  (to the end)

    size_t k = s.find("Nazrul");
    if (k == string::npos) cout << "not found";
    else                   cout << k;    // 5

    string a = "Kazi ", b = "Nazrul";
    cout << a + b;                 // Kazi Nazrul
    a += b;                        // cheaper: no new string

    string t = s;
    t.insert(5, "Kobi ");          // Kazi Kobi Nazrul
    t.erase(5, 5);                // Kazi Nazrul   (undone)
    t.replace(0, 4, "Sultan");     // Sultan Nazrul

    cout << s[0];                  // K
    cout << s.at(0);               // K  — but this one checks the bound

    if (a == b) cout << "same";
    if (a <  b) cout << "a comes first";  // dictionary order

    reverse(t.begin(), t.end());     // lurzaN natluS

    string line;
    getline(cin, line);            // reads spaces too — cin >> does NOT
}

⚠ Three things that catch everyone in the lab

1 · find does not return −1. It returns string::npos, a huge unsigned number. if (k == -1) looks right and is wrong. Always compare against string::npos.

2 · cin >> s stops at the first space. Type Kazi Nazrul and you get back Kazi. Use getline(cin, s).

3 · The exam counts from 1, C++ counts from 0. SUBSTRING(S, 6, 6) on paper is s.substr(5, 6) in code. Read the index set first — the same warning as Class 1.

Section 6 · the last algorithm of Segment 2

Pattern matching — finding P inside T

⏱ 15 min

The problem

You are given a text T and a pattern P. Does P appear inside T, and where?

This is Ctrl+F. It is the search bar on every website you have ever used. And the first algorithm for it is one you can invent yourself in thirty seconds.

The idea. Line P up under the first character of T and compare, character by character. The moment one pair disagrees, stop — slide P one place to the right and start again. Keep sliding until P falls off the end.

Naive pattern matching
MATCH(T, S, P, R, INDEX). T is a text with S characters and P is a pattern with R characters. This algorithm finds INDEX, the position of the first occurrence of P in T, and sets INDEX = 0 if P does not appear.
Step 1. [Initialize] Set K := 1 and MAX := S − R + 1. Step 2. Repeat Steps 3 to 5 while K ≤ MAX: Step 3. Repeat for L = 1 to R: If P[L] ≠ T[K + L − 1], then: Go to Step 5. [End of inner loop] Step 4. [Success] Set INDEX := K. Exit. Step 5. [Slide the pattern one place] Set K := K + 1. [End of Step 2 loop] Step 6. [Not found] Set INDEX := 0. Step 7. Exit. 
// 0-based C++. Returns the index where P starts, or -1.
int match(string t, string p) {
    int n = t.size(), m = p.size();

    for (int k = 0; k <= n - m; k++) {   // n-m+1 shifts
        int l = 0;
        while (l < m && t[k + l] == p[l]) l++;
        if (l == m) return k;             // all m matched
    }
    return -1;
}

int main() {
    string t = "TO BE OR NOT TO BE", p = "NOT";
    cout << match(t, p);      // prints 9

    cout << t.find(p);        // prints 9 — the library does the same thing
}
bestO(m) worstO(n×m) spaceO(1) shiftsn − m + 1

Where the numbers come from

Let T have n characters and P have m.

How many places can P sit? Its first character can go at 1, 2, 3 … up to n − m + 1. Past that, P hangs off the end. So there are n − m + 1 shifts — and yes, that is the UB − LB + 1 counting rule from Class 1 wearing a different hat.

How much work per shift? At most m comparisons.

Worst case: (n − m + 1) × m, which we call O(n × m).
Best case: the very first comparison of every shift fails — about n comparisons in total.

⚠ What makes the worst case actually happen

Press the worst case button above: T = AAAAAAAAAB, P = AAAB.

Every shift matches AAA and only fails on the last character — so no shift ever exits early. 7 shifts × 4 comparisons = 28 comparisons to find one match in a 10-character text.

Repeated characters are the enemy. On ordinary English text the first comparison usually fails and the algorithm is close to O(n) — which is why this "bad" algorithm is still used everywhere.

T has 20 characters and P has 4. How many shifts does the algorithm try in the worst case, and how many comparisons?
17 shifts, 68 comparisons. Shifts = n − m + 1 = 20 − 4 + 1 = 17. Each does at most m = 4 comparisons, so 17 × 4 = 68.

Option 3 is the −1 mistake — the same one that makes people write UB − LB instead of UB − LB + 1. Both ends count.

Dig deeper

?Can we do better than O(n×m)?
Yes — and the idea is worth hearing even though it is outside your syllabus.

When a shift fails after matching AAA, the naive algorithm throws that knowledge away and slides by one. But we already know what those three characters were. Smarter algorithms use that to slide by more than one:

KMP (Knuth–Morris–Pratt) precomputes how far it can safely jump — O(n + m).
Rabin–Karp compares a hash of each window instead of the characters — you will meet hashing in Segment 10.
Trie — the structure behind the Facebook search in Class 1 of Segment 1.

For the exam, know that the naive one is O(n×m) and that better ones exist by name.
?What does the second version of the algorithm in the book do?
Some textbooks give a second algorithm that keeps a table of where the pattern could restart, so it never re-compares characters it has already seen. That is the KMP idea written out longhand.

If the question just says "the pattern matching algorithm", write the one above. It is the one with the n − m + 1 shifts and the two nested loops, and it is what the marking scheme expects.

The definition question

"Define substring, initial substring and terminal substring"

What a full-mark answer looks like

Do not answer in your own words. Give the three-piece definition, then one example of each. That is what the marking scheme is looking for.

?Model answer
A string Y is called a substring of a string S if there exist strings X and Z such that S = X ‖ Y ‖ Z.

If X is an empty string, then Y is called an initial substring of S.
If Z is an empty string, then Y is called a terminal substring of S.

Example. Let S = "TO BE OR NOT TO BE".
• "BE OR NOT" is a substring  [ X = "TO ", Z = " TO BE" ]
• "TO BE OR" is an initial substring  [ X is empty ]
• "NOT TO BE" is a terminal substring  [ Z is empty ]

Add this line for the last mark: if Y is a substring of S then LENGTH(Y) cannot exceed LENGTH(S).

⚠ Where marks go missing
1. Writing "a part of a string" and stopping. No X, no Z, no marks.
2. Swapping initial and terminal. X empty → initial (nothing before it). Say it out loud twice.
3. Giving an example that skips characters. A substring is consecutive.

The counting question

LENGTH and concatenation

?"Find LENGTH(S) where S = 'Kazi Nazrul'"
11.

K-a-z-i is 4, the space is 1, N-a-z-r-u-l is 6.  4 + 1 + 6 = 11.

The space is a character. This one line is the whole question, and it is where most of the lost marks in this topic come from.
?"If S1 = 'Kazi ' and S2 = 'Nazrul', find S1 ‖ S2 and its length"
S1 ‖ S2 = "Kazi Nazrul", and its length is 11.

Note the space is inside S1. If S1 were "Kazi" with no space, the answer would be "KaziNazrul", length 10. Copy the quotation marks from the question exactly — they are telling you where the space is.

The rule: LENGTH(S1 ‖ S2) = LENGTH(S1) + LENGTH(S2).
?"How many substrings does a string of length n have?"
n(n + 1) / 2 non-empty substrings.

Why: pick a start (n ways), then a length that fits. Adding it up gives n + (n−1) + … + 1 = n(n+1)/2.

For n = 4 that is 10. And there are exactly n initial substrings and n terminal ones.

The algorithm question

"Write the pattern matching algorithm and find its complexity"

Worth full marks — and you already have it

This asks for exactly the algorithm in Section 6. Write it with the two nested loops, then state the complexity and justify it in one line. Working C++ is accepted just as happily as the notation — write whichever you are quicker at.

?Model answer — algorithm plus the complexity line
MATCH(T, S, P, R, INDEX). T is a text with S characters, P is a pattern with R characters. This algorithm finds the position INDEX of the first occurrence of P in T, or sets INDEX = 0.

1. [Initialize] Set K := 1 and MAX := S − R + 1.
2. Repeat Steps 3 to 5 while K ≤ MAX:
3.     Repeat for L = 1 to R:
        If P[L] ≠ T[K + L − 1], then: Go to Step 5.
    [End of inner loop]
4.     [Success] Set INDEX := K. Exit.
5.     Set K := K + 1.
  [End of Step 2 loop]
6. [Not found] Set INDEX := 0.
7. Exit.

Complexity. The outer loop runs at most S − R + 1 times and the inner loop at most R times, so the worst case is (S − R + 1) × R, that is O(S × R) — usually written O(n × m). The best case is O(R), when P matches at the very first position. Space is O(1).

⚠ Where marks go missing
1. Writing MAX := S − R. It is S − R + 1. Both ends count.
2. Forgetting Step 6. If you never set INDEX := 0, the algorithm has no answer for "not found".
3. Giving the complexity as O(n) because "there is one loop over the text". There are two nested loops.
?"Trace the algorithm on T = 'AAAAAAAAAB', P = 'AAAB'"
n = 10, m = 4, so MAX = 10 − 4 + 1 = 7 shifts.

Shifts 1 to 6 — each one matches A, A, A and then fails on the 4th character (A against B). That is 4 comparisons each.
Shift 7 — T[7..10] = AAAB. All four match. INDEX = 7.

Total = 7 × 4 = 28 comparisons.

This is the worst case, and it shows why: every shift almost succeeds, so none of them exits early.

In 0-based C++ the same answer is index 6. State which convention you are using.

Asked about strings

?What is the difference between a substring and a subsequence?
"A substring is a consecutive run of characters. A subsequence keeps the order but may skip characters."

Segment 2
?Why is C's strlen O(n) but C++'s .length() O(1)?
"A C string is just a char array ending in '\0' — there is nowhere to keep the length, so strlen has to walk to the terminator and count.

A C++ string is an object that stores its length as a member, so .length() just reads a number."

Why it matters: for (int i = 0; i < strlen(s); i++) re-walks the whole string on every iteration — an accidental O(n²). Compute the length once, before the loop.

?Why does string concatenation in a loop get slow?
"Each + builds a new string and copies both halves. Doing that n times copies 1 + 2 + 3 + … + n characters, which is O(n²)."
