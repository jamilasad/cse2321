Segment 1 ended with complexity. You learned that reading one variable from RAM takes about 10 nanoseconds, and that the machine goes straight to the right box without searching.

Today: how does it know which box? The answer is one formula, and it is the foundation of the next three classes.

1

Section 1

What a linear array actually is

⏱ 7 min

Definition — learn this word for word

A linear array is a list of a finite number n of homogeneous data elements (that is, elements of the same type) such that:

(a) the elements are referenced respectively by an index set consisting of n consecutive numbers;
(b) the elements are stored respectively in successive memory locations.

Three words are carrying the whole definition. Miss any one and it is not an array.

Homogeneous

Every element is the same type, so every element takes the same number of bytes. This is what makes the formula in Section 4 possible.

Consecutive index set

The indices run 1, 2, 3, … with no gaps. Not any set of labels — a run of consecutive numbers.

Successive locations

Element 2 sits immediately after element 1 in memory. No gaps, no scattering. Contrast with the linked list in Segment 3.

The words the exam uses

The number n of elements is called the length or size of the array.
In A[K], the number K is called a subscript or an index, and A[K] is called a subscripted variable.

If nothing is stated, assume the index set is 1, 2, …, N. Note that C and C++ start at 0 — the textbook and the exam usually start at 1. Always read the given index set before you calculate anything.

Section 2

See it in the code you already write

⏱ 6 min

The idea in one sentence

int arr[6]; creates six ordinary int variables — nothing exotic. They are just specially named: instead of six different names you get one name and a number, arr[0] through arr[5].

And because they are laid side by side, that number can be turned into an address by arithmetic. That is the entire trick.

Three lines of C++ you have written many times. Run them one at a time and watch the memory on the right.

Memory — 6 successive cells

Press Run next line.

Indices start at 0

int arr[6] gives you arr[0] to arr[5]. There is no arr[6]. In C++ the lower bound is always 0.

Nothing is cleared for you

Before you assign anything, the cells hold whatever was already there — leftover bytes from some earlier program. Reading them gives you garbage, not zero.

The cells are neighbours

All six sit side by side. That is the "successive memory locations" from the definition — and it is what makes Section 5's formula possible.

The question to hold on to

When you wrote arr[9] = 100; the machine jumped straight to the last cell. It did not walk past the other five.

How did it know where that cell was? That is Section 5.

Section 3

Length — and why the lower bound matters

⏱ 8 min

An array's index set does not have to start at 1. Real ones often do not:

AUTO(2000:2019)

Car sales per year. The index is the year — so it starts at 2000.

STUCGPA(23001:23099)

CGPA per student. The index is the student ID — so it starts at 23001.

So the length is not just "the biggest index".

The formula

Length = UB − LB + 1

UB is the largest index, called the upper bound.
LB is the smallest index, called the lower bound.

Change the bounds and watch it. The "+ 1" is the part people forget.

Length = UB − LB + 1 = 8 − 1 + 1 = 8 elements

⚠ Why "+ 1"

Count the years from 2000 to 2019 on your fingers. It is 20, not 19 — because both ends are included.

2019 − 2000 = 19 is the gap between the first and last. Add 1 to count the first one as well.

Quick check
How many students are in STUCGPA(23001:23099)?
99. 23099 − 23001 + 1 = 99. This exact array appeared on the Spring 2023 Mid Term paper — and the whole question depends on getting this right first.

Section 4

What the computer actually remembers

⏱ 7 min

Memory is a sequence of addressed locations — you saw that strip in Segment 1. An array's elements sit in successive cells of it.

The surprising part

The computer does not keep track of the address of every element.

It keeps only one: the address of the first element, written BASE(LA) and called the base address of LA.

That is all it stores. One address, plus two numbers it already knows:

BASE(LA)

Where the first element sits.

w

The number of words (bytes) per memory cell for this array — 4 for an int, 8 for a double, 1 for a char.

LB

Where the index set starts.

Think about what that means

A million-element array costs the computer one remembered address, not a million.

Everything else is calculated on demand. That is the trade an array makes, and it is why the next section is the most important formula in this segment.

Section 5 · the heart of the segment

The address formula

⏱ 14 min

Learn this. Everything in Segment 2 is built on it.

LOC(LA[K]) = BASE(LA) + w (K − LB)

Read it in plain words: start at the beginning, then jump forward by however many elements you have skipped, each one w bytes wide.

Do not memorise it — build it

Take an array with base address 200, 4 bytes per element, lower bound 1. Where does each element sit? Work down the list.

ElementIndex KSkippedAddress
1stK = 10 elements200  =  BASE
2ndK = 21 element204  =  BASE + 4×1
3rdK = 32 elements208  =  BASE + 4×2
4thK = 43 elements212  =  BASE + 4×3
…………
KthKK − LBBASE + w (K − LB)

There is the whole derivation

Look at the Skipped column: 0, 1, 2, 3 … while the index runs 1, 2, 3, 4. The skipped count is always one less than the index — because the first element skips nothing.

In general that is K − LB. Each skipped element costs w bytes. So you jump w (K − LB) bytes past the base:

LOC(LA[K]) = BASE(LA) + w (K − LB)

Check it against the first row

Put K = LB into the formula: BASE + w(LB − LB) = BASE + 0 = BASE.

The first element sits exactly at the base address, which is what we said in Section 4. A formula that survives its own first case is one you can trust.

Notice what the formula does NOT contain

There is no loop. There is no if. There is no search. It is one multiplication and two additions — the same three operations whether K is 1 or 1,000,000.

The sentence to remember

The time to calculate LOC(LA[K]) is essentially the same for any value of K. Given any subscript K, you can locate and access LA[K] without scanning any other element.

That is what random access means, and it is the array's one superpower. Segment 3 shows you a structure that gives it up — and what it buys in return.

Dig deeper

?Why does C and C++ start at 0?
Because it makes the formula simpler. With LB = 0 the (K − LB) term becomes just K:

LOC(a[K]) = BASE + w × K

One subtraction saved on every single array access, in every program ever written. That is why the language designers chose it.

But the exam usually gives you LB = 1 or something like 23001 — so never assume. Read the index set first.
?What exactly is "w"?
w is the number of bytes one element occupies — sometimes called "words per memory cell" in the textbook.

From Segment 1: char = 1, int = 4, float = 4, double = 8.

Exam questions state it directly — "w = 4 bytes per memory cell" — so you never have to guess. Just substitute it.
?What happens if I ask for LA[K] outside the bounds?
The formula still works — and that is the danger. Ask for LA[100] in an 8-element array and it happily computes BASE + w × 99 and reads whatever is sitting there.

C and C++ do not check. You get a value, and it is somebody else's data. This is exactly the Segment 1 lesson again: it does not crash, it does not warn you, it lies.

This is why vector::at() exists — it checks the bound and throws. v[i] does not.
Quick check
An array of double has BASE = 500, w = 8, LB = 1. What is the address of element 6?
540. LOC = 500 + 8 × (6 − 1) = 500 + 8 × 5 = 500 + 40 = 540.

Option 3 is the classic mistake: multiplying by K instead of K − LB. You have skipped 5 elements to reach the 6th, not 6.

Section 6

Traversal — visiting every element

⏱ 10 min

Traversal is the first of the seven operations from Segment 1: access each element exactly once so it can be processed.

Algorithm (Traversing a Linear Array). Here LA is a linear array with lower bound LB and upper bound UB. This algorithm applies an operation PROCESS to each element of LA.
Step 1. [Initialize counter] Set K := LB. Step 2. Repeat Steps 3 and 4 while K ≤ UB: Step 3. [Visit element] Apply PROCESS to LA[K]. Step 4. [Increase counter] Set K := K + 1. [End of Step 2 loop] Step 5. Exit.

⚠ Caution, straight from the textbook

The operation PROCESS may use variables that must be initialized before it is applied to any element. Your algorithm may need an extra initialising step.

In plain words: if you are counting, set the counter to 0 first. Forgetting Step 1 is the most common way to lose marks on this question.

The worked example

The array AUTO(2000:2019) records how many cars were sold each year. Find NUM — the number of years in which more than 300 were sold.

1. Set NUM := 0. 2. Repeat for K = 2000 to 2019: If AUTO[K] > 300, then: Set NUM := NUM + 1. [End of loop] 3. Return.

The cost

Traversal touches every element exactly once — so it is O(n), always.

Compare that with Section 4: reading one element is O(1), but reading all of them is O(n). That gap is where the rest of this course lives.

Before you go

Three things to take home

⏱ 2 min

1 · Length

UB − LB + 1

Both ends are counted. Never forget the + 1.

2 · Address

BASE + w (K − LB)

It is K − LB, not K. You skipped that many elements.

3 · Why it is fast

One element is O(1), because it is calculated, never searched. All elements is O(n).

Why this one formula matters so much

Next class it becomes the 2D formula. The class after that, a linked list gives it up entirely — and you will finally see what an array is really worth.

Real past question

The traversal module — Spring 2023, Q2(a)

Spring 2023 · Q2(a) · 2 marks · CO3

"Suppose ACAD maintains a linear array STUCGPA(23001:23099) such that STUCGPA[K] contains the CGPA of the student who bears the ID number K. Write a module for each of the following tasks:
i) Print the ID Number of the students who have CGPA above 3.90.
ii) Count the number of students who have CGPA above 3.30."

?Model answer — both modules
First, read the index set. LB = 23001, UB = 23099, so the length is 23099 − 23001 + 1 = 99 students. The ID is the index — that is the whole trick of the question.

(i) Print the IDs with CGPA above 3.90
1. Repeat for K = 23001 to 23099:
        If STUCGPA[K] > 3.90, then: Write: K.
        [End of If structure]
  [End of loop]
2. Return.

(ii) Count those above 3.30
1. [Initialize] Set NUM := 0.
2. Repeat for K = 23001 to 23099:
        If STUCGPA[K] > 3.30, then: Set NUM := NUM + 1.
        [End of If structure]
  [End of loop]
3. Write: NUM.
4. Return.

⚠ Where the marks go missing
1. Looping for K = 1 to 99 instead of 23001 to 23099. The index is the ID.
2. Forgetting Set NUM := 0 in part (ii) — the exact caution from the textbook.
3. Printing STUCGPA[K] in part (i). It asks for the ID, which is K.

The same question, different clothes

The textbook version is AUTO(2000:2019) counting car sales. The exam version is STUCGPA(23001:23099) counting students. It is one pattern: initialise a counter, loop the real index range, test each element, update.

Learn the shape once and you can answer it whatever the story is.

Coming in the next classes

What this formula turns into

The 1-D address formula is not examined on its own — it is examined as its 2-D big brother, which has appeared on all four Mid Term papers.

Autumn 2025 · Q2(b)  ·  and Spring 2025, Spring 2024, Spring 2023

"Consider a 2D array A(4:12, 7:14). i. Find the length of each dimension and the total number of elements in A. ii. If Base(A) = 300 and w = 8 bytes per memory cell, calculate the address of the element A[6, 10] assuming row-major storage order."

Part (i) is this class. Length of the first dimension is 12 − 4 + 1 = 9; the second is 14 − 7 + 1 = 8; total elements = 9 × 8 = 72.

Part (ii) is next-but-one class — the same BASE + w × (how many you skipped) idea, with the skipping counted across rows.

Interview

Asked in almost every interview

?Why is array access O(1)?
Because the address is calculated, not searched.

"The elements are stored in successive memory locations and they are all the same size, so the machine knows the address of element K without looking at any other element — BASE + w × (K − LB). That is one multiply and two adds, regardless of K."

Then earn the follow-up: "and this is exactly what a linked list gives up — its nodes are scattered, so it has to walk from the head."

Segment 2 Segment 3
?Why must array elements all be the same type?
Because the address formula depends on every element being the same width. If element 3 were 2 bytes and element 4 were 8, there would be no way to jump straight to element 7 — you would have to walk and add up sizes as you went, and access would become O(n).

Homogeneity is not a restriction for its own sake. It is the price of O(1) access.
?What is the difference between an index and an address?
An index is the position you write in your code — LA[6], a small human-friendly number.
An address is the actual memory location — 540, a number in the billions-wide RAM strip.

The formula is the translator between them, and it runs on every single array access your program ever makes.
