Section 1

From one dimension to two

⏱ 6 min

Definition

A two-dimensional m × n array A is a collection of m · n data elements such that each element is specified by a pair of integers (such as J, K) called subscripts.

The element with first subscript J and second subscript K is written A[J, K] or A[J][K].

The same thing has three names depending on who is talking:

In programming

a two-dimensional array

In mathematics

a matrix

In business

a table

Which is why 2D arrays are sometimes called matrix arrays.

The convention — get this right or every answer is wrong

A[J, K] means row J, column K. Row first, always.

So in an m × n array, m is the number of rows and n is the number of columns.

Here is the MARKS example from the lecture: 25 students, 4 tests — a 25 × 4 array. Every student gets a row; every test gets a column.

A 5 × 4 slice of it. MARKS[3, 2] is the 3rd student's 2nd test.

Your turn

The full array is MARKS(1:25, 1:4) — 25 students, 4 tests each.

  1. Is it a 25 × 4 array or a 4 × 25 one? What are m and n?
  2. Which mark is MARKS[2, 4]?
  3. Does MARKS[4, 2] mean the same thing?

1. 25 × 4 — m = 25 rows, n = 4 columns. Rows come first in the size, and a row is one student.

2. Student 2's 4th test. Row first: the 2 is the student, the 4 is the test.

3. No — and this is where marks go. MARKS[4, 2] is student 4's 2nd test: a different person, a different test. On a 25 × 4 array MARKS[4, 2] exists, but MARKS[2, 4]'s mirror MARKS[4, 2] only happens to exist because 4 ≤ 25. Ask for MARKS[2, 26] and there is no such column at all.

Row, then column. Every time. Both address formulas in this class start by deciding how many complete rows you skip — get the order wrong and everything after it is wrong too.

Section 2 · the whole problem

Memory is a line. A table is not.

⏱ 9 min

Go back to Segment 1. RAM is one long strip of numbered boxes — there is no such thing as "up" or "down" in it. But a 2D array has rows and columns.

So here is the question the computer must answer

In what order do you lay a rectangle out along a straight line?

There are exactly two sensible answers, and every language picks one.

Your turn

You have a 3 × 4 table and twelve consecutive memory cells to put it in. Nothing else — no gaps, no second array, no pointers.

Which cell does A[2, 3] go in?

There is more than one defensible answer. Find both of them, and say what you assumed each time.

Cell 6, or cell 7 — and both are right. It depends on the order you decided to write the table down in, and there are exactly two sensible ones.

Row by row: row 1 fills cells 0–3, row 2 fills 4–7. A[2,3] is the third element of row 2, so offset 6.

Column by column: column 1 fills 0–2, column 2 fills 3–5, column 3 fills 6–8. A[2,3] is the second element of column 3, so offset 7.

That is the whole section. The two answers have names — row-major and column-major — and every language picks one and never mentions it again.

Row-major order

Store row 1 completely, then row 2, then row 3 …

Used by C, C++, Java, Python.

Column-major order

Store column 1 completely, then column 2, then column 3 …

Used by FORTRAN, MATLAB, R.

Watch it flatten, block by block

The grid is read in one order and written into memory in that order. Press Next and watch a single cell leave the table and take its place in the line — in both layouts at once.

Quick check
A 4 × 5 array stored column-major. At what offset does A[2, 3] sit?
9. Column-major skips whole columns, and a column is M = 4 elements long. Two complete columns come before column 3, so 4 × 2 = 8 elements; then one more to reach row 2. 8 + 1 = 9.

7 is the row-major answer (5×1 + 2), which is the mistake worth knowing you can make. 8 forgets to step down to row 2.

Look at what changed and what did not

The grid is identical. Same 12 values, same rows, same columns. Only the order they were written into memory differs.

That is the entire idea. Row-major and column-major are not two data structures — they are two ways of writing down the same one.

Time to visit every cell

O(M · N)

The walk above is one press per cell — twelve for a 3 × 4 table, thirty-six for 6 × 6. Nothing is skipped and nothing is visited twice, so the count is the number of cells. Every "do something to the whole table" question has this shape, and a nested loop is what it looks like in code.

Section 3

Deriving the address formula

⏱ 9 min

You already know the 1D formula from Class 1:

LOC(LA[K]) = BASE + w (K − LB)

The 2D version is the same idea. The only new question is: how many elements do I skip to reach A[J, K]?

Base(A) base addressw bytes each J K the indices you want LB lower boundUB upper bound

Same five colours as Class 1 — same five symbols.

Your turn

You are storing an m × n table row by row, and you want the address of A[J, K].

How many elements do you have to skip to get there? Build it in two parts:

  • How many complete rows come before row J, and how many elements is each of them?
  • Once you are at the start of row J, how many more to reach column K?

This is Class 1's w (K − LB) with one extra term. You already know the shape.

(J − 1) complete rows come before row J, and each is n elements long — so that is n(J − 1) elements skipped.

Then inside row J you skip (K − 1) more.

Total skipped = n(J − 1) + (K − 1), each costing w bytes. That is the whole formula, and you just derived it.

Column-major is the same sentence with the words swapped: skip (K − 1) complete columns of m elements each, then (J − 1) inside the column.

Row-major — count the skipping

To reach row J, you must skip all the complete rows before it. There are (J − 1) of them, and each holds N elements (N = number of columns).

Then, inside row J, you skip (K − 1) more to reach column K.

Total skipped = N(J − 1) + (K − 1)

Row-major:   LOC(A[J,K]) = Base(A) + w [ N(J − 1) + (K − 1) ]

Column-major — mirror everything

Now you skip whole columns. There are (K − 1) complete columns before column K, and each holds M elements (M = number of rows).

Then inside the column you skip (J − 1).

Column-major:   LOC(A[J,K]) = Base(A) + w [ M(K − 1) + (J − 1) ]

The one-line way to remember which is which

Row-major multiplies by N (the number of columns) — because a whole row is N elements long.
Column-major multiplies by M (the number of rows) — because a whole column is M elements long.

You multiply by the length of the thing you are skipping over. Get that and you never have to memorise either formula.

The lecture's worked example

25 students are given 4 tests, stored in a 25 × 4 array MARKS. Base(MARKS) = 100, w = 4 bytes, row-major. Find the address of MARKS[10, 2] — the 10th student's 2nd test.

LOC(MARKS[10,2]) = Base + w [ N(J − 1) + (K − 1) ] = 100 + 4 [ 4(10 − 1) + (2 − 1) ] = 100 + 4 [ 36 + 1 ] = 100 + 4 × 37 = 248

If MARKS were stored in column-major order instead: 100 + 4[25(2−1) + (10−1)] = 100 + 4[25 + 9] = 236. Same element, different address — because the layout is different.

Time to reach A[J, K]

O(1)

One multiplication and two additions — and that is the whole cost, whatever the size. A 25 × 4 table and a 25,000 × 4,000 table are reached in exactly the same three operations, because the machine calculates the address instead of walking to it. That is what you are buying when you store a table as an array, and it is the sentence to write when an exam asks why the formula matters.

Section 4 · the exam form

When the bounds don't start at 1

⏱ 16 min

Every exam question gives you something like A(4:12, 7:14). The rows start at 4, not 1. So (J − 1) is wrong — you must subtract the real lower bound.

Effective indices

The effective index is how far along a dimension you actually are:

E1 = J − LB1     E2 = K − LB2

And the lengths are the usual UB − LB + 1 from Class 1:

M = UB1 − LB1 + 1     N = UB2 − LB2 + 1

Then the formulas become Base + w [ N·E1 + E2 ] for row-major and Base + w [ M·E2 + E1 ] for column-major.

Quick check
In A(4:12, 7:14), what is the effective index E₁ for the element A[6, 10]?
2. E₁ = J − LB₁ = 6 − 4 = 2 — row 6 is the third row of the array, so two complete rows come before it.

5 is J − 1, which is right only when the bounds start at 1. 6 is J itself. Both are the same slip: subtract the lower bound, not one.

⚠ The three mistakes that cost marks every year

1. Using (J − 1) when LB₁ is not 1. For A(4:12, …) row 6 is the 3rd row, so E₁ = 2, not 5.
2. Multiplying by M instead of N in row-major. You skip whole rows, and a row is N long.
3. Forgetting the +1 in the lengths. 12 − 4 = 8, but there are 9 rows.

Half the class writes a column-major answer. It is the only question on file that asks for one.

Column-major, worked — because no other question makes you do it

Take Y = 0, so Base = 200. The array is A(5:10, 1:10, −2:10) and we want A[7, 5, −1].

Lengths: L₁ = 10 − 5 + 1 = 6, L₂ = 10 − 1 + 1 = 10, L₃ = 10 − (−2) + 1 = 13. Total = 6 × 10 × 13 = 780.

Effective indices: E₁ = 7 − 5 = 2, E₂ = 5 − 1 = 4, E₃ = −1 − (−2) = 1.

Column-major counts from the first dimension inwards — the mirror of row-major:

LOC = Base + w [ L₁( L₂·E₃ + E₂ ) + E₁ ]

= 200 + 4 [ 6 ( 10×1 + 4 ) + 2 ]
= 200 + 4 [ 6 × 14 + 2 ]
= 200 + 4 × 86 = 200 + 344 = 544

The row-major answer for the same element is 1,452 — and the difference is the whole reason the question tells you which order to use. With Y = 6 the base is 206, so the answers are 550 and 1,458.

Quick check
For A(4:12, 7:14), how many elements are there in total?
72. Rows: 12 − 4 + 1 = 9. Columns: 14 − 7 + 1 = 8. Total = 9 × 8 = 72.

56 comes from forgetting both "+1"s (8 × 7). This is part (i) of the exam question, and it is worth a mark on its own.

Three dimensions — same idea, one more layer

⏱ 9 min

🎓 Four of the eight papers use a 3D array

Spring 2024: "Consider an array B(1:8, −5:5, −10:5). Find the length of each dimension and the number of elements. Suppose Base(B) = 150 and w = 4. Find the effective indices E₁, E₂, E₃ and the address of B[2, −3, 2] assuming row-major order."

Spring 2023: the same with A(3:10, 1:10, −3:10) and A[8, 6, 4].

Your turn

Part (i) of Spring 2024 is worth marks on its own, and it needs nothing from this section. Do it before you read on.

B(1:8, −5:5, −10:5)

  1. How long is each of the three dimensions?
  2. How many elements does B hold altogether?

One rule, three times — Class 1's UB − LB + 1. Nothing about three dimensions changes it.

L₁ = 8 − 1 + 1 = 8   L₂ = 5 − (−5) + 1 = 11   L₃ = 5 − (−10) + 1 = 16

8 × 11 × 16 = 1,408 elements.

The two negative lower bounds are the whole question. 5 − (−5) is 10, not 0 — and then the + 1. Almost every mark lost on this part is lost to a minus sign.

Quick check
In Spring 2023's array A(3:10, 1:10, −3:10), how long is the third dimension?
14. L₃ = 10 − (−3) + 1 = 13 + 1 = 14.

13 forgets the + 1 — the commonest slip in the segment. 10 reads the upper bound as the length, which is only ever right when LB = 1.

Do not panic at the third subscript. It is the same counting, one level deeper. Picture a stack of tables: to reach a cell you skip whole tables, then whole rows, then individual cells.

LOC = Base + w [ ( E1 × L2 + E2 ) × L3 + E3 ]

Read it from the inside out

E₁ × L₂ — skip E₁ whole slabs, each L₂ rows tall
+ E₂ — then skip E₂ more rows
× L₃ — every one of those rows is L₃ elements long
+ E₃ — finally skip E₃ elements inside the row

Same principle every time: multiply by the length of what you are skipping.

Section 6

n dimensions — one rule behind all three formulas

⏱ 9 min

You have now written what looks like three different formulas: one for a line, one for a table, one for a stack of tables. They are one formula. Here is the machine underneath it, and it does not care how many dimensions you give it.

The declaration, in general

An n-dimensional array C is declared with n pairs of bounds, C(LB1:UB1, LB2:UB2, …, LBn:UBn), and holds

L1 · L2 · … · Ln   elements,   where Li = UBi − LBi + 1

Memory, as always, is one line. So the n subscripts have to be put in some order, and there are only two orders anyone uses.

Watch the subscripts turn like an odometer

Each row below is one dimension. The lit box is that subscript's current value. Press Next and watch which row moves — because that, and nothing else, is the difference between row-major and column-major at any number of dimensions.

Your turn

Run it once in row-major and once in column-major, then answer from what you saw:

  1. Which row of wheels moves on every single press?
  2. What has to happen before the row above it moves once?
  3. So how many cells does one tick of that upper row step over?

Your third answer is a multiplication. It is already in the formula you wrote in Section 5.

1. In row-major the last subscript moves every press; in column-major the first does. That one swap is the entire difference.

2. The fast wheel must run through all of its values and wrap back to its lower bound. Only then does the wheel above it tick.

3. It steps over L cells — the whole length of the wheel below it. That is where the multiplication comes from: every level of the formula multiplies by the length of the level beneath it, because that is how many cells one tick of this level crosses.

The general formula

Write the odometer down as arithmetic and you get this. Each bracket is one carry.

Row-major:   LOC = Base + w [ ( … ( ( E1·L2 + E2 )·L3 + E3 ) … )·Ln + En ]

Column-major:   LOC = Base + w [ ( … ( ( En·Ln−1 + En−1 )·Ln−2 + En−2 ) … )·L1 + E1 ]

You have not learned three formulas. You have learned one, three times.

nRow-major offsetWhere you met it
1E1Class 1 — K − LB
2E1·L2 + E2Section 3 — N·E1 + E2, and L2 is N
3(E1·L2 + E2)·L3 + E3Section 5, exactly as printed
4((E1·L2 + E2)·L3 + E3)·L4 + E4one more bracket, and no new idea

Each new dimension wraps the whole previous answer in one more bracket. If you can write the n = 2 line you can write any of them — which is why the exam only ever needs to set two or three.

Time to reach C[K1, …, Kn]

O(1)

The brackets add n − 1 multiplications — but n is fixed the moment the array is declared, so it is a constant, not an input. A four-dimensional array is reached in a fixed handful of operations however large it grows. Every array, at every number of dimensions, is O(1) to index.

Quick check
A 4-dimensional array with lengths L = (2, 5, 3, 7) is stored row-major. How many cells does one tick of K2 step over?
21. Below K2 there are two more wheels, and both must run out before it ticks: L3 × L4 = 3 × 7 = 21.

7 counts only the fastest wheel — that is what one tick of K3 steps over. 5 is K2's own length, which is how many ticks it gets, not how far each one goes.

The triplet representation

Instead of storing every cell, store only the non-zero ones — each as a triple:

( row , column , value )

Plus one header row recording the dimensions and how many non-zeros there are. Everything not listed is understood to be 0.

RowColumnValue

⚠ It is not free

Each triple stores three numbers instead of one. So the triplet form only wins when fewer than about a third of the elements are non-zero. Push the slider past 33% and watch the saving turn negative.

You also lose O(1) access — to read A[J,K] you now have to search the triplet list instead of calculating an address. Classic time–space tradeoff, once again.

Your turn

A 100 × 100 matrix holds 250 non-zero values and nothing else.

  1. How many numbers does the full array store? How many does the triplet form store?
  2. Is it worth it — and by how much?
  3. Now push the slider up. At what percentage does the saving disappear? Say why, in one line.

Each triple is three numbers, and there is one header row on top.

1. The full array stores 10,000 numbers — every cell, zero or not. The triplet form stores 250 × 3 + 3 = 753.

2. A saving of 9,247 numbers, about 92%. At this density it is not an optimisation, it is the difference between fitting in memory and not.

3. One third. Each value costs three numbers instead of one, so the moment more than 1/3 of the cells are non-zero the triples cost more than the cells they replace. Sparse is a bet that the zeros outnumber the values three to one, and above 33% the bet loses.

Space · full array

O(M · N)

Space · triplets

O(k)

The full array pays for every cell whether or not anything is in it; the triplet form pays only for the k values that exist, at three numbers each. This is the whole reason sparse representation exists — and the reason it stops being worth it once k climbs past a third of M · N.

Time to read A[J, K]

O(k)

And here is what it costs. In the full array the address is calculated — the O(1) of Section 3. In a triplet list there is no formula, so you search the k entries for a row and column that match. You bought the space by selling the constant-time access, which is the trade to name if an exam asks what sparse representation costs.

Dig deeper

?Special sparse shapes worth knowing
Some matrices are sparse in a predictable pattern, and then you can do better than triplets:

Diagonal matrix — only the main diagonal is non-zero. Store just n values in a 1D array.
Tri-diagonal — the diagonal plus the band either side. Store about 3n.
Upper / lower triangular — everything above or below the diagonal is zero. Store n(n+1)/2 — a little under half.

The idea is always the same: if you can predict where the zeros are, you do not have to store them or their coordinates.
?Where do sparse matrices actually appear?
Social networks. Rows and columns are users; a 1 means "follows". With 3 billion users and a few hundred follows each, well over 99.99% is zero.

Search engines. Documents against words — most documents contain almost none of the vocabulary.

Recommendation systems. Users against films — you have rated a handful out of thousands.

In every case, storing the full matrix is physically impossible, so sparse representation is not an optimisation — it is the only way the system can exist at all.

Section 8 · solving one, step by step

Write a module for a square matrix

⏱ 8 min

Every address question so far has been arithmetic. This one asks you to write an algorithm, and it has been set twice in the same words.

Autumn 2023 Q2(c) · Autumn 2022 Q2(c)3 marks

Let A be an n × n square matrix. Write a module which
i) Find the number NUM of zero elements in A.
ii) Find the SUM of the elements above the diagonal i.e. elements A[I, J] where I < J.

Your turn

Answer these three before you look at any code.

  1. The main diagonal is where I = J. So which is "above the diagonal" — I < J or J < I? Draw a 4 × 4 grid and mark them if it helps.
  2. How many cells are above the diagonal of a 4 × 4 matrix?
  3. The module has to count zeros and add up those cells. How many times must it walk the matrix?

For part 2, count what is left after you remove the diagonal and split the rest in half.

1. I < J. Row 1 column 3 is above; row 3 column 1 is below. The row index is the smaller one above the diagonal — and if you ever doubt it, A[1, 4] is the top-right corner, which is plainly above.

2. Six. Sixteen cells, minus four on the diagonal, leaves twelve split evenly above and below: n(n − 1) / 2 = 4 × 3 / 2 = 6.

3. Once. Both tests are about the same cell, so both fit inside the same visit. Two separate loops would be a correct answer and a worse one — same order, twice the work, and twice as much to get wrong.

The module, walked

Written for a general N, run here on a 4 × 4 so you can watch every pass. The diagonal is drawn dashed. Every If is landed on and coloured by its answer — green for true, red for false — which is what "show each step" means when an exam asks for it.

Simulator NUM and SUM in one pass
1. Set NUM := 0 and SUM := 0. 2. Repeat for I = 1 to N: 3. Repeat for J = 1 to N: 4. If A[I, J] = 0, then: 5. Set NUM := NUM + 1. 6. If I < J, then: 7. Set SUM := SUM + A[I, J]. 8. [End of step 3 loop] 9. [End of step 2 loop] 10. Write: NUM, SUM. 11. Return.
n b p r 1 / 68
1

Time to answer both parts

O(n²)

The module visits each of the n² cells exactly once and does two constant-time tests on it. Nothing can be cheaper: you cannot count the zeros without looking at every cell. Two separate loops would also be O(n²) — the order would not change, but the work would double, and that is the difference an examiner reads as understanding.

What earns the three marks

Initialise both counters before the loops, not inside them — a Set SUM := 0 in the wrong place is the single commonest way to lose this question.

Write N, not 4. The question says n × n; a module hard-coded to one size has not answered it.

End both loops explicitly and finish with Write and Return. The exam's own algorithms are written that way, and it costs you one line to match them.

Before you go

The exam answer, in five lines

⏱ 3 min

Whatever array they give you, write these five lines

1. Lengths    M = UB₁ − LB₁ + 1  ·  N = UB₂ − LB₂ + 1
2. Total      M × N
3. Effective   E₁ = J − LB₁  ·  E₂ = K − LB₂
4. Substitute   Base + w [ N·E₁ + E₂ ]   (row-major)
5. Arithmetic   one number

Three dimensions is the same five lines

Line 1 gains an L3, line 3 gains an E3, and line 4 becomes Base + w [ (E₁·L₂ + E₂)·L₃ + E₃ ]. One more bracket, and no new idea — which is exactly what Section 6 is for, and why a four-dimensional array would not be a new question either.

Row-major

Base + w[ N·E₁ + E₂ ]

Multiply by N, the number of columns — a row is N long.

Column-major

Base + w[ M·E₂ + E₁ ]

Multiply by M, the number of rows — a column is M long.

One idea, three classes

1D, 2D, 3D, n-D — it has been the same sentence every time: Base, plus w times how many elements you skipped.

Only the counting of "how many you skipped" gets harder, and Section 6 showed that even that is one rule: multiply by the length of the thing you are skipping over, once per dimension. The formula never actually changed.

Every address question we have on record

?Autumn 2025 Q2(b) — A(4:12, 7:14), Base 300, w 8, row-major [3 marks]
"Consider a 2D array A(4:12, 7:14). i. Find the length of each dimension and the total number of elements in A. ii. If Base(A) = 300 and w = 8 bytes per memory cell, calculate the address of the element A[6, 10] assuming row-major storage order."

(i) Lengths
M = 12 − 4 + 1 = 9 rows    N = 14 − 7 + 1 = 8 columns
Total = 9 × 8 = 72 elements

(ii) Effective indices
E₁ = 6 − 4 = 2    E₂ = 10 − 7 = 3

Address, row-major
LOC(A[6,10]) = Base + w [ N·E₁ + E₂ ]
              = 300 + 8 [ 8×2 + 3 ]
              = 300 + 8 × 19
              = 452

Column-major, if they had asked: 300 + 8[9×3 + 2] = 532.
?Spring 2025 Q2(b) — same array, Base 500, w 4 [2.5 marks]
Identical array, only Base and w change.

M = 9, N = 8, total = 72
E₁ = 6 − 4 = 2    E₂ = 10 − 7 = 3
LOC = 500 + 4[8×2 + 3] = 500 + 4×19 = 576

Notice how little changes. Learn the five-line method once and the numbers are just arithmetic.
?Spring 2024 Q2(b) — 3D: B(1:8, −5:5, −10:5) [2.5 marks]
"Consider an array B(1:8, −5:5, −10:5). i. Find the length of each dimension and the number of elements in B. ii. Suppose Base(B) = 150 and w = 4 words per memory cell for B. Find the effective indices E₁, E₂, E₃ and the address of the element B[2, −3, 2] assuming B is stored in row-major order."

L₁ = 8 − 1 + 1 = 8
L₂ = 5 − (−5) + 1 = 11
L₃ = 5 − (−10) + 1 = 16
Total = 8 × 11 × 16 = 1,408 elements

(ii) Effective indices
E₁ = 2 − 1 = 1    E₂ = −3 − (−5) = 2    E₃ = 2 − (−10) = 12

Address
LOC = Base + w [ ( E₁×L₂ + E₂ ) × L₃ + E₃ ]
     = 150 + 4 [ ( 1×11 + 2 ) × 16 + 12 ]

     = 150 + 4 [ 208 + 12 ]
     = 150 + 4 × 220
     = 1,030

?Explain row-major and column-major — Autumn 2025 Q2(a) [3 marks]
"Explain how to represent a two-dimensional array in computer memory using row-major order and column-major order. Illustrate your answer with an appropriate example or diagram."

Model answer. Computer memory is a one-dimensional sequence of addressed cells, but a 2D array is a rectangle of rows and columns. The array must therefore be linearised — written out in some fixed order — and there are two conventions.

Row-major order stores the array row by row: all of row 1, then all of row 2, and so on. Used by C, C++ and Java.
Column-major order stores it column by column: all of column 1, then column 2. Used by FORTRAN.

Example — a 2 × 3 array A:
col 1col 2col 3
row 1102030
row 2405060
Row-major in memory:    10 20 30 40 50 60
Column-major in memory: 10 40 20 50 30 60

Then give the two address formulas and you have the full 3 marks.

✅ The pattern across all four years

Part (i) is always lengths and total — pure UB − LB + 1 from Class 1. Part (ii) is always effective indices then substitute. It has been row-major every single time, but learn column-major anyway — it is one swap of M and N.

Interview

What they ask about 2D arrays

?Why does looping over a 2D array row by row run faster than column by column?
A genuinely common interview question, and Segment 1 already gave you the answer.

In C++ arrays are row-major, so a row is contiguous in memory. Walking along a row reads neighbouring bytes, and the CPU pulls a whole cache line at a time — so most reads are already in cache.

Walking down a column jumps N elements each step, so nearly every read is a fresh trip to RAM — 60–100 ns instead of ~1 ns.

Same Big-O. Very different real time. That distinction — complexity versus constant factor — is exactly what the question tests.
?Is a 2D array really two-dimensional in memory?
No. Memory has one dimension only. The rectangle exists in your head and in the notation; the machine sees a single line and does arithmetic to fake the second dimension.

"A[J][K] is just syntax for Base + w(N·E₁ + E₂)."

That is why int a[3][4] and int a[12] occupy exactly the same 48 bytes.
?When would you use a sparse representation?
When most entries are zero and the matrix is too big to store fully. The rule of thumb is under about one third non-zero — past that, the three numbers per triple cost more than the zeros you avoided.

Give a concrete case: "a social graph of 3 billion users where each follows a few hundred — over 99.99% zero. The full matrix cannot exist; the sparse form is a few hundred billion triples."

Then state the cost: you lose O(1) access. Reading A[J,K] becomes a search rather than a calculation.

Problem 1 · LeetCode 240

Search a matrix sorted both ways

O(M + N)

The problem

Every row of A is sorted left to right, and every column is sorted top to bottom. Given ITEM, say whether it is in the matrix — and do better than looking at every cell.

Your turn

The obvious answer is a nested loop: M × N comparisons. You can do much better, and the trick is where you start.

  1. If you stand on the top-right corner and it is bigger than ITEM, what do you know about its whole column?
  2. If it is smaller than ITEM, what do you know about its whole row?
  3. So how many cells can one comparison throw away?

The top-right corner is the largest of its row and the smallest of its column. No other corner has both properties.

1. Everything below it in that column is even bigger, so if the corner already exceeds ITEM the entire column is out. Step left.

2. Everything to its left in that row is even smaller, so if the corner is below ITEM the entire row is out. Step down.

3. One whole row or one whole column — M or N cells at a time. Each comparison ends a row or a column for good, and there are only M + N of them, so the search cannot take more than M + N steps.

Simulator The staircase, from the top-right corner
ITEM =
1. Set I := 1 and J := N. [top-right] 2. Repeat while I ≤ M and J ≥ 1: 3. If A[I, J] = ITEM, then: 4. Write: found at I, J. Return. 5. If A[I, J] > ITEM, then: 6. Set J := J − 1. [drop the column] 7. Else: 8. Set I := I + 1. [drop the row] 9. [End of loop] 10. Write: not found. Return.
n b p r 1 / 1
1

Nested loop

O(M · N)

Staircase

O(M + N)

On a 1,000 × 1,000 matrix that is a million comparisons against two thousand. Nothing clever happened: the matrix was already sorted, and the staircase is simply the algorithm that uses what the data already told you. Sorted input that you search linearly is the commonest wasted opportunity in the course.

Problem 2 · LeetCode 73

Set matrix zeroes, without a second matrix

O(1) space

The problem

Wherever A[I, J] is 0, the whole of row I and the whole of column J must become 0. Do it in place — no copy of the matrix, and no list of rows and columns to fix afterwards.

Your turn

Two answers come to mind first, and both have something wrong with them.

  1. Zero each row and column as soon as you find a 0. Walk through what happens on the very next cell you read. Why is the answer wrong?
  2. Keep two lists — rows to clear, columns to clear — then clear them at the end. This is correct. What does it cost?
  3. The matrix already has M + N cells you could write a mark into without needing any extra memory at all. Which ones?

For 3, you need one cell per row and one per column, and they have to be somewhere you will read before you overwrite them.

1. The zeros you write are indistinguishable from the zeros that were there to begin with. The next cell you read is a 0 you just wrote, so you clear its row too, and the whole matrix collapses to zero. An in-place algorithm must never destroy the input it has not finished reading.

2. It works, and it costs O(M + N) extra memory. For most purposes that is fine — but the question asked for constant space, and there is a way.

3. The first row and the first column. If row I needs clearing, write a 0 into A[I, 1]; if column J needs clearing, write it into A[1, J]. The marks live inside the matrix, and every one of them is a cell that is going to be zeroed anyway. The only awkward cell is A[1, 1], which two marks would have to share — so the first row and first column get one true/false flag each, checked before anything is overwritten.

Simulator Marks stored inside the matrix
1. Set R0 := false, C0 := false. 2. Repeat for J = 1 to N: if A[1,J] = 0 then R0 := true. 3. Repeat for I = 1 to M: if A[I,1] = 0 then C0 := true. 4. Repeat for I = 2..M, J = 2..N: [leave the marks alone] 5. If A[I,J] = 0, then A[I,1] := 0 and A[1,J] := 0. 6. Repeat for I = 2..M, J = 2..N: [now read the marks] 7. If A[I,1] = 0 or A[1,J] = 0, then A[I,J] := 0. 8. If R0, then: clear the whole first row. 9. If C0, then: clear the whole first column. 10. Return.
n b p r 1 / 1
1

Extra space

O(1)

Time

O(M · N)

Two flags, and nothing else. The matrix is walked three times instead of once, so the time is still O(M · N) — three passes over n² cells is the same order as one. Trading a constant number of passes for all of your extra memory is almost always the right trade, and recognising when the data can hold its own bookkeeping is the actual skill here.
