((A + (B * C)) − D). Inside out: B C *, then A B C * +, then A B C * + D −.

Check yourself — 1 of 5
What is (A + B) / (C − D) in postfix?
A B + C D − /. Each bracket becomes its own postfix, A B + and C D −, and the / goes after both.

Section 2

Why a stack

⏱ 8 min

Compare A + B * C − D with its postfix, A B C * + D −. The letters come out in the same order, so an operand can go straight to the answer. Only the operators move: each one has to wait until it is safe to write it.

Your turn

Read A + B * C − D from the left. When must * be written to the answer? When must +?

Both when − arrives. − ranks below * and level with +, so both must be finished before −. * waited on top of +, so * leaves first.

The rule, from that

A newcomer operator first pops every waiting operator of the same or higher precedence to the answer, then waits itself. The last to wait is the first to leave, so the waiting room is a stack.

Check yourself — 2 of 5
+ is waiting on the stack, and * arrives. What happens?
* waits on top of +. + is lower than *, so it does not have to be done first.

POLISH(Q, P), and the C++

⏱ 10 min

A "(" gets level 0, so the operator loop always stops at it. The simulator runs A + B * C − D both ways.


  

    
Your turn

Section 6
Three traps

    ⏱ 5 min
  


  

    
Your turn

    
A − B + C?

    
    
A B − C +. When + arrives, − is waiting with the same precedence, so − is popped first. Left to right.

  


  
    
    
  • A ")" pops back to its "(", and both brackets vanish. Neither ever goes into P.
    • 
    
  • Chained ↑. POLISH pops on "same or higher", so A ↑ B ↑ C becomes A B ↑ C ↑, which means (A ↑ B) ↑ C. Mathematics reads it as A ↑ (B ↑ C), which is A B C ↑ ↑. No exam has ever chained ↑; follow the algorithm.
    • 
  

  
Both traps are in Section 4's simulator, at the end of the list.


  

    
Check yourself — 3 of 5

    
What is A − B + C in postfix?

    

      
      
      
    

    
A B − C +. A B C + − would mean A − (B + C), a different number.

Section 7
Brackets

    ⏱ 12 min
  


  
Spring 2026 final Q1c: read a string of ( and ) only, use a stack to check it is correctly nested, and print Valid or Invalid. An opener waits on the stack; a closer takes one off. Run the first mode of the simulator.

  

  

    
Your turn

    

      
Now allow three kinds: ( [ {. What must change in the code? Write it, then switch the simulator to three kinds.

      
Hint: with one kind, the stack only ever holds "(". With three, what must you check when a closer arrives?

    

    
    
Push whichever opener arrives. When a closer arrives, the top must be its own opener; if not, the answer is Invalid. ([)] fails exactly there. At the end the stack must still be empty.

The exam's own examples, checked:

  

    ()()[]{}({})[]([{}]){()}
    ({})[]){](([])}
  


  

    

      With one kind of bracket, is a stack even needed?
      
No. A counter does the same job: add 1 for "(", take 1 for ")", fail if it ever goes below 0, and pass only if it ends at 0. The stack only ever holds "(", so its size is all that matters. With three kinds a counter is not enough, because the order of the openers matters too. Spring 2026 asks for a stack anyway, so write the stack.

    

  


  

    
Check yourself — 4 of 5

    
Is ([)] valid?

    

      
      
    

    
Invalid. When ")" arrives, the top is "[", not "(". The counts match, but the nesting does not.

Section 8
Next greater element

    ⏱ 8 min
  


  
Not examined. It is in the syllabus, and the lab sets LeetCode 496.

  
For each number, find the first bigger number to its right. If there is none, the answer is −1.


  

    
Your turn

    
Do 13 17 3 5 33 by eye.

    
    
17 33 5 33 −1. By eye, each number looks right until it finds a bigger one. That is up to n looks each: O(n²).

  


  
One pass does it instead. The stack holds the numbers still waiting for an answer, by index. Each new number answers every smaller one on top, then waits itself.


  

    

      Simulator
      Next greater element
      
    

    

      

        

          

            

            

          

          

        

        

      

      

      

        
        
        
        
        n b p r
        1 / 1
      

      

      
1

    

  


  
The numbers waiting on the stack are always in decreasing order, from the bottom up. A stack kept in order like that is a monotonic stack; CSE-2430 takes it further. Each index is pushed once and popped at most once, so the whole pass is O(n).


  

    
Check yourself — 5 of 5

    
In 13 17 3 5 33, what is the next greater element of 33?

    

      
      
      
    

    
−1. Nothing comes after 33, so it is still waiting on the stack at the end, and gets −1.
