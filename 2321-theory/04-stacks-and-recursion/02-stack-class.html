Fix 2: send the stack in

    ⏱ 10 min
  


  
The second fix: write each function once, and pass it the stack to work on.

  

  
int &topIdx is the reference you met in Segment 3 as Node*&. push must change the caller's own index, so it takes the variable itself, not a copy.

  
    
    
  • Every new stack still needs two new variables.
    • 
    
  • Every call carries the stack's insides, even where they are irrelevant: size needs only the index.
    • 
    
  • The index goes by reference to push and pop, and by value to top and size.

Section 4
The class

    ⏱ 12 min
  


  
A class describes what every stack has and does, once. Each object of the class is one stack, with its own copy of the variables.

  
    
    
  • Member variables: arr and topIdx.
    • 
    
  • Member functions: push, pop, top and size. Inside them, arr and topIdx mean the object's own.
    • 
    
  • A constructor, Stack(), runs once for every object that is made. It sets topIdx = -1.
    • 
    
  • Stack a, b; makes two stacks. a.push(13) pushes onto a.
    • 
  

  
For now everything in the class is public. Below, Section 3's program is converted line by line. The overflow and underflow checks of Stacks 1 travel unchanged inside push and pop; they are left out here so both programs fit on screen.


  

    
Your turn

    
Section 3 had three problems: new variables for every stack, insides passed in every call, and the index passed two different ways. Before you convert: which of them will be gone at the end?

    
    
All three. One line declares a stack, no call carries an array or an index, and a.push(5) can only mean a. The mix-up of Section 3 cannot even be written.

Section 5
Private from whom?

    ⏱ 11 min
  


  

    
Your turn

    
A class can mark members private. Private from whom?

    
    
Not from the person who runs the program. From other code. A class has two coders: the one who builds Stack, and the one who uses it in main. private is a contract between them. The builder promises push, pop, top and size; the user promises to touch nothing else.

  


  
Everything is still public. The user knows the exam: "TOP = 0 means empty". So he writes one line to empty a. It compiles.

  


  

    
Your turn

    
What does a.size() print?

    
    
1. In this class, empty is topIdx = -1. topIdx = 0 means one item, 13. The user broke the stack without calling push or pop.

  


  
Now move arr and topIdx under private:. Only the class's own functions can use them.

The rule

    
Keep everything private unless you are forced to make it public. Here only push, pop, top, size and the constructor need to be public. It pays off again in Section 7.

Section 6
What it costs

    ⏱ 5 min
  


  

    
push · pop · top · size
O(1)

    
Each one changes or reads one cell and one index. Nothing shifts, so the cost is the same with 5 items or 5 million.

  


  
The space is another story. All N cells are reserved from the start, used or not. This is the textbook's time–space trade-off: a big N wastes space, and a small N overflows.


  

    
Your turn

    
An editor keeps an undo history. Most users undo twice; a few undo 10,000 times. How big should N be?

    
    
No N is right. A big N wastes memory for most users, and a small N overflows for the few.

The linked stack: only the private part changes

    ⏱ 12 min
  


  

    
Your turn

    
Which two Segment 3 operations are O(1) and work at the same end of a list?

    
    
insertFirst and deleteFirst. So the head is the top. The tail end will not do: deleteLast is O(n) even with a tail pointer.

  


  
So the private part becomes Node* head; and int cnt;. push is insertFirst and pop is deleteFirst. The public names stay the same, so main is not touched. There is no overflow test any more, and underflow is head == nullptr. Switch the storage and run the same main.

Four things to carry into the next class

    
    
      
  • Two stacks on global variables means copies of everything, or parameters that can be mixed up.
    • 
      
  • A class keeps each stack's data together. Every object is one stack.
    • 
      
  • Keep everything private unless you are forced not to.
    • 
      
  • With the data private, the storage can change from an array to a list without touching main.

Model answers
What to write


  
Two stacks in one array

  
Stack A[1] starts at STACK[1] and grows to the right; stack A[2] starts at STACK[N] and grows to the left. Overflow happens only when the two tops meet, so neither stack is limited to half the array. Empty is TOP[1] = 0 and TOP[2] = N + 1.

  

  
The question's POP has no N in its signature, but the underflow test for A[2] needs it. Write N as known, or add it to the parameters, and say so.

  
A worked example with N = 8: push 13, 17, 3 onto A[1], then 5, 33, 40, 41, 42 onto A[2].

  

    
STACK[1..8]TOP[1]TOP[2]Next PUSH

    
13, 17, 3, 42, 41, 40, 33, 534TOP[1] + 1 = TOP[2]: OVERFLOW

  


  
getMin in O(1)

  
Keep a second stack, mn, whose top is always the minimum of the main stack. push(x) also pushes x onto mn when x is less than or equal to mn's top. pop() also pops mn when the value removed is mn's top. getMin() reads mn's top. Every operation is one or two pushes or pops: O(1).

  

  
Pushing 13, 17, 3, 5, 3 gives minimums 13, 13, 3, 3, 3. Four pops then give 3, 3, 13, 13. The second 3 needs the ≤: with <, popping it would lose the minimum.


  
The undo/redo program

  
Two stacks and three cases. Type pushes onto undo and clears redo. Undo and Redo move one value between them. At the end, pour undo into a third stack to print it from the bottom.
