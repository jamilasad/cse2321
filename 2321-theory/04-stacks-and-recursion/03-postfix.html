Section 1

Why infix needs rules

⏱ 7 min

The way you write maths puts the operator between its two operands: A + B. That is infix notation.

Your turn

2 + 3 * 4. Two students get two answers. What decides which one is right?

Precedence. * comes before +, so the answer is 14. Without that rule, 2 + 3 first gives 20. Brackets would settle it too: 2 + (3 * 4).

The textbook's Example 6.5 shows the cost of the rules. In the exam, ↑ is the power sign; in code it is written ^.

The expression2 ↑ 3 + 5 * 2 ↑ 2 − 12 / 6
Pass 1: ↑8 + 5 * 4 − 12 / 6
Pass 2: * and /8 + 20 − 2
Pass 3: + and −26

The expression was read three times, once for each level of precedence.

Section 2

Three ways to write one expression

⏱ 8 min

The operator can go in three places.

  • Infix: between the operands. A + B
  • Prefix, or Polish notation, after the Polish mathematician Jan Łukasiewicz: before them. + A B
  • Postfix, or reverse Polish notation: after them. A B +

To convert by hand, bracket every operation, then move each operator out of its brackets, one bracket at a time. The bracket in square brackets is already done.

(A + B) * C  →  [A B +] * C  →  A B + C *
InfixPrefixPostfix
(A + B) * C* + A B CA B + C *
A * (B + C)* A + B CA B C + *
(A + B) / (C − D)/ + A B − C DA B + C D − /

Neither prefix nor postfix needs a bracket: the order of the symbols already says what happens first. Prefix is named here once and never examined. The rest of the segment is postfix.

Your turn

Write A + B * C in postfix.

A B C * +. Bracket it first: A + (B * C). The inner bracket becomes B C *, then the + goes after: A B C * +.

Check yourself — 1 of 5
What is (A − B) * C in postfix?
A B − C *. The bracket A − B becomes A B −, then * C goes after it. The third option is prefix.

Section 3

Watch it work

⏱ 8 min

The textbook's Example 6.6: P = 5, 6, 2, +, *, 12, 4, /, −. The exam writes commas so that 5, 6, 2 is not read as 562, and so that −4 is read as one operand. Read P from left to right, with one stack and two moves:

  • A number goes on the stack.
  • An operator takes the top two off, works them out, and puts the result back on.
Your turn

In 8, 3, −, the operator takes 3 off first, then 8. Which of the two goes on the left of the minus?

8, the second one taken off. 8 − 3 = 5. It went on first, so it was written first.

Section 4

Algorithm 6.5, and the C++

⏱ 14 min

The textbook writes the same two moves as Algorithm 6.5. It adds a sentinel, a ")" on the end of P, so the loop knows where to stop. The C++ stops at the end of the array instead, which does the same job.

The code uses STL's stack<double>: a division can give a fraction, and Stacks 2's class holds only ints. The simulator runs Example 6.6 both ways. Switch between them with the buttons above it.

Your turn

The algorithm calls the top element A and the next one B, and computes B ⊗ A, not A ⊗ B. Why that order?

B was pushed first, so B was written first: it is the left operand. For + and * the order does not matter; for −, / and ↑ it does.

Section 6
Solve for N

    ⏱ 13 min
  


  
Autumn 2023 mid Q3c, set again as Autumn 2024 final Q1c: 9, −4, +, 3, ↑, N, 4, −, 2, *, +, 5, −. For what value of N is the result XY, the last two digits of your ID?


  

    
Your turn

    
Evaluate it with N left as a letter.

    
    
2N + 112. 9 + (−4) = 5, and 5 ↑ 3 = 125. Then (N − 4) * 2 = 2N − 8, and 125 + 2N − 8 = 2N + 117. Last, 2N + 117 − 5 = 2N + 112. The stack now holds expressions, not only numbers.

  


  

    
Then solve

    
2N + 112 = XY, so N = (XY − 112) / 2. XY is at most 99, so N is always negative. If your ID ends in 26, N = −43. If XY is odd, N ends in .5.

    
Spring 2023 mid asks the same of 3, 1, −, 2, ↑, N, 4, /, 2, *, +, 5, −. That one comes to N/2 − 1, so N = 2·XY + 2. Divisions are taken to two decimal places, as the exam instructs.
