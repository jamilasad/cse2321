Section 2
What a call costs

    ⏱ 8 min
  


  

    
Your turn

    
fact(4) and factLoop(4) both give 24. Which one needs more memory while it runs?

    
    
fact(4). Five frames sit on the stack at once, one for each box. factLoop(4) has one frame, with r and k in it.

  


  
Depth. Every call puts a frame on the stack, and the frame stays until the call returns. You saw in Class 5, Section 3 what happens with no stop: the stack fills, and the program crashes. A stop does not help a run that is simply too deep. The stack holds a few megabytes, so sum(a, n) on a million numbers can run out of room. sumLoop uses one frame for any n.


  
Work done again. fib(4) made 9 calls in Class 5, and the tinted boxes did work that was already done.


  

    
Your turn

    
fib(3) makes 5 calls and fib(4) makes 9. How many calls does fib(5) make?

    
    
15. fib(5) is one call, and it calls fib(4) and fib(3): 1 + 9 + 5 = 15. Each new n adds the last two counts and 1.

Section 3
A loop can’t do this

    ⏱ 10 min
  


  

    
Your turn

    
Write every string of 0s and 1s of length 2. Then every one of length 3.

    
    
Length 2: 00, 01, 10, 11. Length 3: 000, 001, 010, 011, 100, 101, 110, 111. Each place doubles the count, so length n has 2n strings.

  


  

    
Your turn

    
Print the strings of length 2 with while loops. Then of length n, where n is typed in when the program runs.

    
    

      

      
Length 2 takes two loops, one inside the other: one loop for each place. Length 3 takes three. Length n takes n loops, and you cannot write a number of loops that is only known when the program runs.

    

  


  
Recursion can. Name it: bits(s, n) prints s followed by every way to fill n more places. It puts a 0 in the next place and trusts a call for the rest, then does the same with a 1. The stop: when n == 0, nothing is left to fill, so it prints s.

Each box makes two calls, so the boxes form a tree, not a line. A loop walks a line. To walk a tree, it must remember every branch it has not taken yet. That is a stack, and recursion keeps it for you.

  
The same tree lists every subset. Read 1 as “take item k” and 0 as “leave it”: 00, 01, 10 and 11 are the four subsets of two items.

Section 5
Hanoi with your own stack

    ⏱ 14 min
  


  

  
Tower of Hanoi from Class 7 makes two calls a box, so its boxes form a tree. Now write it with no call to itself.


  

    
Your turn

    
Without recursion, what must you write down to remember the work still waiting?

    
    
Each waiting job: how many disks, and which pegs. Those are the four numbers a call gets: n, beg, aux and end. A stack of them is the call stack, written by hand.

  


  
A Task holds the four numbers. {n, beg, aux, end} fills its four fields in that order. Each pass of the loop pops one job. One disk: move it. More than one: push its three parts back as jobs.


  

    
Your turn

    
The job {3, A, B, C} has three parts: 2 disks A → B, then 1 disk A → C, then 2 disks B → C. In what order do you push them, so the first part comes off first?

    
    
The last part first: {2, B, A, C}, then {1, A, B, C}, then {2, A, C, B}. A stack gives back the last thing pushed, so the first part goes in last.

Section 6
Loop or recursion?

    ⏱ 6 min
  


  

    
Your turn

    
Loop or recursion? (a) The sum of an array. (b) Every string of length n. (c) fib(40).

    
    
(a) A loop: one call a box. (b) Recursion: two calls a box. (c) A loop: the recursion makes 331,160,281 calls; the loop makes 40 passes.

  


  

    
The rule

    
    
      
  • One call a box (fact, sum, GCD, digits): write the loop. Same answer, one frame.
    • 
      
  • The same calls again and again (fib): write the loop, and keep the answers you need.
    • 
      
  • Two or more calls a box (bits, Hanoi): write recursion. A loop needs a stack you write by hand.
    • 
      
  • Data made of smaller copies of itself (a list): recursion reads the way the data is built.
    • 
      
  • Watch the depth. A run a million calls deep can fill the stack.
    • 
    

  


  

    
Check yourself — 4 of 5

    
Which one is best left recursive?

    

      
      
      
    

    
Tower of Hanoi: two calls a box. digits and GCD make one call a box, so a loop does them with one frame.

  


  

    
Check yourself — 5 of 5

    
sum(a, n) is called on an array of 1,000,000 numbers. What can go wrong?

    

      
      
      
    

    
The stack can run out of room. The stop is there, but a million frames must sit on the stack before the first one returns. sumLoop needs one frame.

Section 7
The page to keep

    ⏱ 4 min
  


  
    
    
  • One call a box makes a line of boxes, and a loop walks it. Work on the way up: start at the stop and climb. Work on the way down: start at the top.
    • 
    
  • A call costs a frame. A run too deep fills the stack. fib(n) makes 2 × fib(n + 1) − 1 calls; the loop makes n passes.
    • 
    
  • Two calls a box make a tree. n loops inside each other cannot be written for an unknown n; bits(s, n) can.
    • 
    
  • A list is a node and a smaller list. printBack keeps its numbers in frames; printBackLoop needs a stack<int>.
    • 
    
  • Hanoi with your own stack: pop a job; one disk, move it; more, push its three parts, the last one first.

Exam & Interview · Recursion 4

    
What interviews ask

    
No past exam asks why recursion. Interviews do. Four questions, each answered the way an interviewer wants.

  








  
How often
Not in an exam yet

  
No CSE-2321 exam from Spring 2022 to Spring 2026 asks why recursion, or asks for a loop in place of a recursive function. The nearest question is 5! with the stack drawn, in three finals, and Class 5 covers it.

  
The questions below are interview questions. Each answer is short on purpose: say it in under a minute.






  
Interview
When do you use recursion instead of a loop?

  
    
    
  • Recursion when each call makes two or more calls (all strings of length n, Tower of Hanoi), or when the data is made of smaller copies of itself (a list). The code follows the problem, and the call stack keeps track of the work still waiting.
    • 
    
  • A loop when each call makes one call (factorial, sum, GCD). It gives the same answer with one frame.
    • 
    
  • A loop when the recursion repeats work, as fib does, or when it would run very deep.
    • 
  






  
Interview
Turn this recursive function into a loop

  

  
The answer. One call a box, and the work (a * x) happens on the way up. So the loop starts at the stop’s answer, 1, and multiplies by x once for each box:

  

  
The recipe. One call a box: start at the stop’s answer and do one box’s work a pass. Two calls a box: keep a stack of the calls still waiting, and push them in reverse, as Hanoi did.






  
Interview
What does recursion cost?

  
    
    
  • Memory: one frame for each call still waiting. fact(n) needs n + 1 frames at once, O(n) space; factLoop needs O(1).
    • 
    
  • Stack overflow: the stack holds a few megabytes, so a run that goes deep enough crashes, even with a correct stop.
    • 
    
  • Work done again: fib(n) makes 2 × fib(n + 1) − 1 calls, which grows by about 1.6 times with each n: O(2n) as a bound. The loop is O(n).
    • 
    
  • Each call takes time of its own: making the frame and removing it. A loop pass does not.
    • 
  






  
Interview
Can every recursion be written as a loop?

  
Yes. The computer runs a recursion with a loop and a stack: the call stack. You can write the same stack yourself. Tower of Hanoi on a stack<Task> is the example: pop a job, and push its parts, the last one first.

  
For one call a box, no stack is needed: a plain loop does it. With two or more calls a box, the stack you write is longer and easier to get wrong than the recursion.
