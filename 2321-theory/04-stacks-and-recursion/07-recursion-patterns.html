Palindrome

    ⏱ 10 min
  


  
A palindrome reads the same both ways: LEVEL, NOON, ROTOR. The same four steps:

  
    
    
  • Name it. pal(s, l, r) says whether the letters s[l] to s[r] read the same both ways.
    • 
    
  • Play with it. LEVEL: yes. LEVER: no. EVE, the middle of LEVEL: yes.
    • 
    
  • Trust pal(s, l + 1, r - 1) to answer for the middle.
    • 
    
  • Use it. The two ends must match too. If they do not, the answer is false, and the middle is never asked.
    • 
    
  • Stop. Trace down. LEVEL goes (0, 4), (1, 3), (2, 2): one letter left. NOON goes (0, 3), (1, 2), (2, 1): no letters left. Both read the same both ways. Two base cases, one line: l >= r.

Ackermann, traced only

    ⏱ 8 min
  


  
The Ackermann function is a definition to evaluate, not one to design. It takes two whole numbers, m and n, and Lipschutz defines it in three cases. On paper you substitute: write each line from the one above it, one call at a time.


  

    

      Simulator
      Ackermann by substitution
      
    

    

      

      

        

          Find
          
          
          
        

        

          
(a) If m = 0, then A(m, n) = n + 1.

          
(b) If m ≠ 0 but n = 0, then A(m, n) = A(m − 1, 1).

          
(c) If m ≠ 0 and n ≠ 0, then A(m, n) = A(m − 1, A(m, n − 1)).

        

        

        

        

      

      

        
        
        
        
        n b p r
        1 / 1
      

    

  


  

    
Your turn

    
Find A(1, 3) on paper before you run it.

    
    
5, after 8 calls. A(1, 3) = A(0, A(1, 2)) = A(0, A(0, A(1, 1))) = A(0, A(0, A(0, A(1, 0)))) = A(0, A(0, A(0, A(0, 1)))) = A(0, A(0, A(0, 2))) = A(0, A(0, 3)) = A(0, 4) = 5.

  


  
Always work out the innermost call first: it is the only one whose two numbers are known. Case (a), m = 0, is the base criteria: it answers without a call. Every call lowers m, or keeps m and lowers n, so the run always ends. It grows very fast: A(4, 2) already has 19,729 digits.


  

    
Check yourself — 5 of 5

    
What is A(1, 2)?

    

      
      
      
    

    
4: A(1, 2) = A(0, A(1, 1)) = A(0, A(0, A(1, 0))) = A(0, A(0, A(0, 1))) = A(0, A(0, 2)) = A(0, 3) = 4. 5 is A(1, 3).

The page to keep

    ⏱ 4 min
  


  
    
    
  • A function that prints is written in the four steps: name it, play with it, trust a smaller call, use it. The base case comes last.
    • 
    
  • Work before the call happens on the way down. Work after the call happens on the way up.
    • 
    
  • rec(n) prints the binary digits of n, last one first. Swap its two lines and they come out in order.
    • 
    
  • pal checks the two ends and trusts the middle. It stops at l >= r.
    • 
    
  • TOWER is three lines: N − 1 disks to AUX, one disk to END, N − 1 disks onto it. It takes 2n − 1 moves: O(2n).
    •

Question and answer
Tower of Hanoi, and its complexity

  

    
FinalSpring 2024 · Q1 (c)4 marks

    
Explain the Tower of Hanoi problem. Also analysis the complexity of Tower of Hanoi problem.

  

  
The problem. Three pegs, A, B and C. Peg A holds n disks, each smaller than the one below it. Move all n disks to peg C, using B as the auxiliary. Two rules: only one disk moves at a time, and a larger disk is never placed on a smaller one.

  
The recursive solution, for n disks from BEG to END using AUX:

  
    
    
  1. Move the top n − 1 disks from BEG to AUX.
    2. 
    
  2. Move the top disk from BEG to END: BEG → END.
    3. 
    
  3. Move the top n − 1 disks from AUX to END.
    4. 
  

  

  
The complexity. Let T(n) be the number of moves. Steps 1 and 3 each take T(n − 1), and step 2 takes one move:

  
T(1) = 1  ·  T(n) = 2T(n − 1) + 1

  
T(n) = 2T(n − 1) + 1 = 4T(n − 2) + 2 + 1 = … = 2n−1T(1) + 2n−2 + … + 2 + 1 = 2n − 1

  
So n = 3 takes 7 moves and n = 4 takes 15. The running time is O(2n): each extra disk doubles the work.
