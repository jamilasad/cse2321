Where we are

Seven classes of linked list, and every one of them drawn the same way: nodes in memory, arrows between them, a pointer called head.

That drawing is one way of writing a list down. It is not the one your book uses, and it is not the one on the board when the question says “let LIST be a linked list in memory”. Today you learn the other one — and then everything from Class 1 to Class 7 goes on a single page.

Why a book would write it this way

The notation is older than the assumption that every language has pointers, and it was designed to be written on paper. It has one real advantage over your drawing: the addresses are visible and small. “Row 6” is a thing you can write in an answer book; 0x7ffd41c0 is not.

It has one real disadvantage, and it is worth saying out loud: the table is a fixed size. Eight rows is eight rows. That is not a property of linked lists — it is a property of drawing one inside an array.

Check yourself — 1 of 7
In the table above, someone swaps the contents of rows 2 and 7 — both the INFO and the LINK cells move together — and fixes every LINK that pointed at 2 or 7. What happens to the list?
Nothing changes. A node’s position in the table is not its position in the list. Move a node to a different row, fix the one LINK that pointed at it, and the list reads exactly the same.

That is the whole idea in one experiment, and it is why the answer to “where is the third node?” is always follow the links and never look at row 3.

Section 2

Where a new node comes from

⏱ 9 min

In C++ you wrote new Node and stopped thinking about it. On paper there is no new. The table has eight rows, the list uses four, and the other four have to come from somewhere.

Your turn

Look at the table in §1 again. The list uses rows 3, 6, 2, 7. Rows 1, 4, 5, 8 are free — and their LINK cells are not empty.

Read those four LINK cells. What are the free rows telling you?

Row 1 links to 4, row 4 links to 8, row 8 links to 5, row 5 links to NULL. The free rows are a linked list of their own.

It has a name and a start pointer, exactly like the real one. The book calls it the free-storage list, and its start is called AVAIL. Here AVAIL = 1.

So the table holds two lists that never touch: the one you care about, starting at START, and the one the rows come from, starting at AVAIL. Every insert moves one row from the second to the first. Every delete moves one back.

—

Two sentences that answer most of the question

To insert: take the row at the front of AVAIL, move AVAIL on to the next free row, fill the new row in, and re-link the one node in front of it.

To delete: re-link the node in front of it, then put the row back on the front of AVAIL.

Both take the row from the front of AVAIL and give it back to the front. Nobody searches the free list — that is what makes both of these two assignments rather than a walk.

The row is not wiped

After the delete, row 2 still has 30 sitting in its INFO cell. Nothing erased it — the row was simply put back on the free list, and the next insert will write over it.

That is the same fact as Class 3 §6: delete gives the memory back, it does not clear it. Here you can see the value still lying there.

Check yourself — 2 of 7
After the insert and the delete above, which row will the very next insert use?
Row 2. The delete put it on the front of AVAIL, so AVAIL = 2 now and row 2 links on to 4.

Free rows come back in the reverse of the order they were freed — the free list behaves like a stack, which is Segment 4’s first structure. It is also why the row numbers in an exam answer will not look tidy, and why that is not a mistake.

The two-way list, in the same table

⏱ 8 min

Class 7 gave the node a second pointer. On paper that is a third column. The rows do not move, START does not change, and AVAIL works exactly as it did in §2.

Books disagree about the names. Some write FIRST for START, some write NEXT and PREV instead of FORW and BACK, and some put BACK on the left. Copy the headings you are given. A column is defined by its name, never by where it sits.

—

The line that pays for the column

Step 1 of the delete is Set FORW[BACK[LOC]] := FORW[LOC].

In §2 you could not write that line. The one-way table has no BACK, so its delete had to be handed PREV — and when nobody hands it to you, you walk the list from START to find it. Here the row before is already written down, one cell away.

That is Class 7’s whole argument, in the exam’s own notation: a second column does not make a list faster to search. It makes a node you are already holding removable.

The two rows where those two lines are wrong

If LOC is the first row then BACK[LOC] is NULL, and there is no FORW[NULL] to write into — you set START := FORW[LOC] instead. If it is the last row then FORW[LOC] is NULL, and you set LAST := BACK[LOC].

Two ifs, one line each. Every list an exam has printed has been long enough that the node it asks you to delete is in the middle, so you will not see them fail — write them anyway.

Check yourself — 3 of 7
You are given the two-way table above and asked to find the row holding 20. Compared with the one-way table of §1, how much of that work does the BACK column save you?
None of it. Searching is still O(n) and still starts at START. You could start at LAST and walk backwards instead, but that is the same n rows read in the other order.

The column is not there to help you find a node. It is there for the moment after you have found one — which is why the operation it changes is delete, and the operation it does not change is search.

Section 4

Writing a procedure in this notation

⏱ 8 min

You met the rules for writing an algorithm in Class 1: numbered steps, := for assignment, a Repeat that names the steps it repeats, and Exit. at the end. Put those together with INFO and LINK and you can write any list procedure without a line of C++.

Your turn

Write, in that notation, a procedure that prints every value in the list. Four steps is enough.

You already know it in C++. The only new thing is the spelling.

1. Set P := START. 2. Repeat Steps 3 and 4 while P ≠ NULL: 3. Write: INFO[P]. 4. Set P := LINK[P]. [End of Step 2 loop.] 5. Exit.

Compare it with the loop you have written twenty times. P := START is Node* p = head;. P ≠ NULL is p != nullptr. P := LINK[P] is p = p->next. Not one idea is new.

Now one that has to remember something as it goes. This is the shape three of the last six papers asked for — walk the list and come back with an answer.

—

Three lines you will write every time

Every procedure that walks a list, in any of the last six papers, is these three lines with something different in the middle:

Set P := START. — go to the front
Repeat while P ≠ NULL: — stop at the end
Set P := LINK[P]. — take one step

Get those three written down and the question is half answered before you have read what it wants counted.

The first value is not zero

A maximum starts at INFO[START], not at 0 — a list of negative numbers would come back with the wrong answer. A sum starts at 0 and a count starts at 0, but a maximum or a minimum starts at the first value in the list, and then the walk begins at the second node.

That is the one line in this shape that is easy to lose a mark on.

Check yourself — 4 of 7
A question asks for the sum of the even values in LIST. Which part of the procedure above changes?
Only the inside. SUM := 0 and P := START to begin; inside the loop, If INFO[P] is even, then: Set SUM := SUM + INFO[P]. The walk itself is untouched.

You cannot skip nodes in the loop condition, because there is no way to reach node k+2 without passing through k+1. Every list procedure visits every node; what changes is what it does when it gets there.

Section 5

Saying what a linked list is

⏱ 7 min

You have built one seven times. Now say what it is, in a sentence, to somebody who has not.

Your turn

Write your definition down before you read on. One or two sentences, no code, no drawing.

Then compare it with the one below — not to see whether you were right, but to see which word you left out.

“A linked list is a collection of nodes stored anywhere in memory. Each node has two parts: an information field holding the value, and a link field holding the address of the next node. A separate pointer, START or head, holds the address of the first node, and the last node’s link field is NULL.”

The word to check for is address. “The link field points to the next node” says the same thing with the definition inside it — it explains linked using links. Saying that the field holds an address is what shows you know why the nodes can be scattered, and it is the half of the sentence that is worth having.

Against an array

The other half of the question is always the comparison. Do not answer it as a list of adjectives — answer it as four trades, each with its reason.

What you are doingArrayLinked listBecause
Getting element kO(1) — arithmetic on the base addressO(n) — you have to walkthe elements are adjacent, or they are not
Inserting at the frontO(n) — every element shiftsO(1) — two assignmentsnothing has to move to make room
Growingfixed at declarationone node at a time, while it runsthe nodes need no unbroken block
Memory per valuejust the valuethe value and a pointerthe link has to live somewhere

One sentence that carries the whole comparison

“An array pays at insert time to be fast at read time; a linked list pays at read time to be fast at insert time.”

Say that, then give one row of the table as evidence, and you have answered a five-mark question in three lines.

Check yourself — 5 of 7
Someone writes: “A linked list is better than an array because it is dynamic.” What is missing?
The cost. “Better” on its own is not an answer to a comparison question, and a marker cannot give it much. A list is not better than an array — it is faster to grow and slower to read, and both halves come from the same fact.

Whenever you claim an advantage here, add the sentence that begins “the price is…”. It is one clause, and it is usually the difference between half the marks and all of them.

How it is marked

The reason is the mark. A complexity on its own earns very little. “O(n), because deleting the last node needs the node before it, and the only way to reach it is from the front” earns all of it — and it is one extra sentence.

On the table question, show the table after every step, not just at the end. If the final table is wrong but the two intermediate ones are right, most of the marks are still there. If there is only one table and it is wrong, there is nothing to give marks for.

Two minutes before you start writing

Read the whole paper first and find the notation it is written in. If it says “let LIST be a linked list in memory” and mentions INFO and LINK, answer in that notation throughout. If it says “write an algorithm or C/C++ function”, use C++ and stay in it.

What loses marks is mixing them in one answer. Pick the one the question is written in, and do not change halfway.

Check yourself — 6 of 7
A question gives you a table and says: “insert 50 after the node with value 20, then delete the node with value 35. Show the table.” What is the first thing to write?
AVAIL and the row it hands you. Every mark in that question depends on it: the new node’s row number, the new value of AVAIL, and where the freed row goes back to. Write AVAIL = _ at the top of your answer before you touch the table.

The final table is one mark. The intermediate ones, and the AVAIL bookkeeping, are the rest.
Check yourself — 7 of 7
Last one, and it is the whole segment in a sentence. Why can a linked list not use binary search?
Reaching the middle costs what the search was trying to save. Binary search is fast because A[mid] is one piece of arithmetic. On a list, finding the middle is n/2 steps — and then finding the middle of the half is more steps again.

A list can perfectly well be sorted, and scattered memory is why there is no arithmetic — but the sentence that earns the mark is the one about the cost of reaching the middle. This is never a question on its own; it is the reason inside “which is better for searching, and why?”

Read the top two rows together

The definition question and the table question are on five of six papers each, and they are usually the same question — part (a) asks what a linked list is, part (b) hands you a table and asks you to change it.

Between them they are worth more than everything else in this segment put together. If you are short of time, §1, §2 and §5 of today are the whole of your revision.

The one that is always there

The table question, worked

It arrives in one of two forms. Either you are given a table and asked to change it, or you are given a list and asked to draw the table. Both are the same knowledge.

What it asksWhat earns the marks
“Read the list from the table.” Follow START, then the LINK column. Write the row numbers as well as the values — 3(10) → 6(45) → 2(30) → 7(20). It shows the marker you followed links instead of reading rows top to bottom.
“Insert ITEM after …” Four things, in this order: the row you took from AVAIL, the new value of AVAIL, the new node’s LINK, and the predecessor’s LINK. Miss the AVAIL update and you lose a mark on a question you otherwise got right.
“Delete the node with …” Re-link the predecessor, then put the freed row on the front of AVAIL. The freed row keeps its old INFO — do not erase it, and do not be surprised that it is still there.
“Show the table.” Draw it after each step, not only at the end. Two correct intermediate tables and a wrong final one still earns most of the marks; one wrong table earns none.

The three mistakes that cost marks here

1. Forgetting AVAIL entirely. The list is right, the free list is untouched, and the answer is half done.

2. Putting the freed row back at the end of AVAIL. It goes on the front. AVAIL is a stack, not a queue.

3. Renumbering the rows to make the list tidy. The whole point is that the rows are in no order. Leave them where they are.

Next[2005] := 1502 · Prev[1502] := 2005
A→C→F→D→E

Three ways this question loses marks

1. Reading the table top to bottom. The first printed row is Book C, and the list starts at Book A. Find the NULL in the Previous column first.

2. Changing one pointer per link. Every join in a two-way list is two cells. Four for an insert, two for a delete — count them in your answer so the examiner can see them.

3. Leaving the deleted row unexplained. Book B’s row still holds 2005 and 1502 after the delete. Either strike it out or write one line saying the node is free now. Do not silently leave it looking like part of the list.

Where not to spend your time

Never asked, in any of the six papers

Your textbook chapter is long, and the previous decks follow it closely. Several of its topics have never appeared on a paper. They are worth knowing exist; they are not worth revising.

In the bookWhat to do with it
Garbage collectionKnow the phrase means “the system reclaims unused nodes by itself”. That is all.
OVERFLOW and UNDERFLOW as conditionsThey appear as one line inside the insert and delete procedures. They have never been a question.
AVAIL as a set of algorithm stepsYou need AVAIL as a column in a table, which is §2. Nobody has been asked to write the free-list algorithm.
Polynomial representationNot once. Skip it.
Header and trailer nodes; grounded header listsThe circular header list is asked about; these variants are not.
A plain circular list without a headerKnow it as a definition, in one sentence.
COUNT as a named procedureYou will be asked to walk and count something. You will not be asked for “the COUNT algorithm”.
Reversing a linked listNever on a paper. It is in Class 5 because it is the classic interview question and because it is repeated insertFirst.
“Why can binary search not be used?”Never a question on its own — only ever the reason inside “which is better for searching, and why?”. Learn it as a sentence to deploy, not a topic.

What that buys you

Nine topics you do not have to revise. Put the time into the table question and the definition — between them they are on five of six papers and they are the two things most students do least practice on, because neither of them involves writing code.

One sentence to have ready for either room

“A linked list trades constant-time access for constant-time insertion, and everything else about it follows from that one trade.”

It answers the exam’s comparison question and an interviewer’s “when would you use one?”, and it is true of every variation in this segment.
