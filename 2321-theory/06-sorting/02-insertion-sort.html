Section 1

Cards in your hand

⏱ 4 min

You hold 3, 7 and 9, in order. You pick up a 5.

379   5
Your turn

Where does the 5 go? Which cards move?

Between 3 and 7. The 7 and the 9 move one place right. The 3 does not move.

That is insertion sort. The left part is always sorted. Take the next value, move the bigger ones one place right, and drop it in the gap.

Section 3

The algorithm

⏱ 8 min

Now the same idea as code. TEMP holds the value being placed. PTR walks left from the cell before it. While A[PTR] is bigger than TEMP, A[PTR] moves one place right.

Exam notation


    

    

      
C++

      

    

  


  

    
Your turn

    

      
The loop line, PTR ≥ 1 and TEMP < A[PTR], makes two tests. What does each one do?

      
Hint: say TEMP is smaller than every value before it. Where does PTR end up?

    

    
    

      
TEMP < A[PTR] stops the walk at the right place: the first value that is not bigger.

      
PTR ≥ 1 stops the walk at the front of the array. It only matters when TEMP is the smallest so far and PTR reaches 0.

    

  


  

    
The test reads left to right

    
It stops at the first part that is false. When PTR = 0, PTR ≥ 1 is false, so A[0] is never read. C++'s && works the same way. That is why ptr >= 0 comes first.

  


  

    
Check yourself — 2 of 7

    
TEMP is smaller than every value before it. Which test ends the walk?

    

      
      
      
    

    
PTR ≥ 1. Every value TEMP meets is bigger, so TEMP < A[PTR] stays true. Only the bounds test stops the walk, at PTR = 0. TEMP then goes into A[1].

Section 6
Best case, worst case

    ⏱ 10 min
  


  

    
FinalAutumn 2025 · Q3 (b)4 marks

    
Analysis the complexity of insertion sort algorithm when the algorithm is implemented in a sorted list of n elements.

  


  

    
Your turn

    

      
The list is already sorted. How many comparisons does each pass make? How many shifts?

    

    
    

      
One comparison, no shifts. A[K − 1] is not bigger than A[K], so the test fails at once. Over n − 1 passes: n − 1 comparisons.

    

  


  

    

      Simulator
      Sorted against reversed
      
    

    

      

      

        

          
Sorted input 

          

          
Reversed input 

          

        

      

      

        
        
        
        
        n b p r
        1 / 1
      

      

      
1

    

  


  
On the reversed list, pass K compares and shifts K − 1 times. TEMP walks all the way to the front. The total is 1 + 2 + … + (n − 1) = n(n − 1)/2. On random data, TEMP walks about halfway: about n(n − 1)/4.


  

    
Best · sorted input
O(n)

    
Worst · reversed
O(n²)

    
Sorted input costs one comparison per pass: n − 1 in all. Reversed input shifts every pair: n(n−1)/2. The average is still O(n²). Space is O(1), one TEMP.

  


  

    
Check yourself — 5 of 7

    
Insertion sort on a sorted list of 100 values. How many comparisons?

    

      
      
      
      
    

    
99. One per pass, for K = 2 to 100. 4,950 is the worst case. 0 forgets that each pass must look once before it knows nothing moves.

One test fewer: the sentinel

    ⏱ 8 min
  


  
Every round of the loop makes two tests. The first, PTR ≥ 1, is false only once: when TEMP is the smallest so far.


  

    
Your turn

−∞. Then TEMP < A[0] is always false, so the walk stops at PTR = 0 by itself. The test PTR ≥ 1 can go.

      The cost, and why C++ keeps the test
      
    
      The array needs one extra cell before the data, A[0]. In the worst case, each pass also compares once against −∞: n − 1 more comparisons in all. The order, O(n²), does not change.
      
    
      A C++ array has no cell before a[0], so C++ code usually keeps ptr >= 0. The sentinel version is the one on the slides and in the textbook. Write it in the exam.

      Nearly sorted data, and stability
      
    ⏱ 5 min
  
      

  
      
    
      FinalSpring 2026 · Q3 (b) (i)part of 3 marks
      
    
      Analyze and identify the most optimal sorting algorithm for each of the following scenarios, providing a concise justification based on performance efficiency: Processing a stream of nearly-sorted data where elements arrive sequentially with minimal inversions …
      
  
      

  

  
      Insertion sort. It costs n − 1 comparisons plus one shift per out-of-order pair. Few such pairs means nearly linear time. It also handles values one at a time, as they arrive.

      Question and answer
      Write the algorithm, and its time complexity
      
  
      
    
      FinalSpring 2024 · Q3 (c) · Autumn 2022 · Q3 (c) asks the first sentence only3 marks
      
    
      Write an algorithm to sort an array A of n elements using insertion sort. What is the time complexity?
      
  
      
  
      
  
      Time complexity. In the worst case, a list in reverse order, pass K makes K − 1 comparisons: f(n) = 1 + 2 + … + (n − 1) = n(n − 1)/2 = O(n²). On average about half that, n(n − 1)/4 = O(n²). In the best case, a list already sorted, each pass makes one comparison: n − 1 = O(n).
      

      


      
  
      Question and answer
      A list that is already sorted
      
  
      
    
      FinalAutumn 2025 · Q3 (b)4 marks
      
    
      Analysis the complexity of insertion sort algorithm when the algorithm is implemented in a sorted list of n elements.
      
  
      
  
      In a sorted list, A[K − 1] ≤ A[K] for every K. So in each pass, the test TEMP < A[PTR] is false the first time: one comparison, and nothing moves. Step 5 puts TEMP back into A[K].
      
  
      There are n − 1 passes, for K = 2, 3, …, n. So
      
  
      f(n) = 1 + 1 + … + 1 = n − 1 = O(n)
      
  
      This is the best case. The worst case, a list in reverse order, is n(n − 1)/2 = O(n²).

      Question and answer
      Nearly sorted data
      
  
      
    
      FinalSpring 2026 · Q3 (b) (i)
      
    
      Processing a stream of nearly-sorted data where elements arrive sequentially with minimal inversions.
      
  
      
  
      Insertion sort. Its cost is about n plus the number of out-of-order pairs, so on nearly sorted data it runs in close to linear time. It inserts each value as it arrives, which suits a stream. It is also stable.
