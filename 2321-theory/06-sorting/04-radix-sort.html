Section 1

Ten buckets are enough

⏱ 5 min

Counting sort on 170, 45, 75, 90, 802, 24 needs a count for every value from 0 to 802: 803 counts for six numbers.

Your turn

A post office sorts letters by postcode. It does not have a pigeonhole for every postcode. How could it sort them with only ten pigeonholes?

Sort by one digit at a time. A digit has only ten values, 0 to 9, so ten pigeonholes are enough for each round.

Radix sort does this with numbers. It starts with the last digit, the units, and works left.

Section 3

Why each pass must keep the order

⏱ 7 min
Your turn

Radix sort drops numbers into buckets and takes them out again. Does it matter in which order a bucket gives its numbers back?

Yes, when two numbers share a bucket. They arrive in the order the earlier passes left them. If the bucket gives them back in a different order, that work is lost.

Sort 46, 17 and 42. Pass 2 runs twice: first with each bucket keeping the order, then with the order mixed.

Simulator Keep the order, or mix it

The order after each pass

n b p r 1 / 1

Pass 1 put 42 before 46, because 2 is less than 6. In pass 2 both have tens digit 4, so only the order they came in can keep them right. Keep that order, and the result is sorted. Mix it, and the work of pass 1 is lost. In pass 1 every bucket held one number, so there was nothing to mix.

A pass that keeps equal digits in the order they came in is stable. Every pass of radix sort must be stable.

Check yourself — 2 of 8
Pass 1 gives 51, 23, 58. In pass 2, bucket 5 gets 51, then 58, and gives back 58 first. What is the result?
23, 58, 51, which is wrong. Bucket 2 gives back 23. Bucket 5 gives back 58 before 51. Pass 1 had put 51 first, and mixing the order lost it.

So each bucket must give its numbers back in the order they came in. The next section's code does exactly that.

Pass 1 gives 170, 90, 802, 24, 45, 75. Write the order after pass 2, the tens digit.

802, 24, 45, 170, 75, 90. Tens digits: 802 → 0, 24 → 2, 45 → 4, 170 and 75 → 7, 90 → 9. 170 went into bucket 7 before 75, so it comes out first.

The last pass decides

    
Each pass sorts the whole list again. The last pass sets the final order. So the most important digit, the hundreds, must come last.

  


  

    
Check yourself — 4 of 8

    
Which pass decides the final order?

    

      
      
      
    

    
The last pass. An earlier pass only matters when the last pass sees a tie: equal numbers keep the order it left them in.

Section 6
How many passes, and what it costs

    ⏱ 9 min
  


  
The number of passes, d, is the number of digits in the biggest value. Shorter numbers get zeros in front.

  
Each pass puts n numbers into buckets and collects them from 10 buckets: n + 10 steps.


  

    
Time
O(d(n + 10))

    
Space
O(n + 10)

    
d passes of n + 10 steps. When d is small and fixed, that is O(n). Like counting sort, it never compares two values.

  


  

    
Your turn

    

      
Sort one million 11-digit phone numbers. Counting sort or radix sort?

    

    
    

      
Radix sort. Counting sort would need a count for every 11-digit value: 100 billion counts. Radix sort needs 11 passes of ten buckets each.

    

  


  
Any base b: b buckets

  
Ten buckets come from base 10, because a decimal digit has ten values. Radix means base. In base b, a digit has b values, so each pass needs b buckets.

  
    
    
  • Each pass puts n numbers into b buckets and collects them: n + b steps.
    • 
    
  • With d digits in base b, radix sort costs O(d(n + b)) time and O(n + b) space.
    • 
  

  
The same number has fewer digits in a bigger base. Here is 802:

Sorting names with radix sort

    ⏱ 12 min
  


  
Radix sort works on names too. The textbook (Lipschutz) first describes it as the way many people alphabetize a long list of names. There the radix is 26: one bucket for each letter.

  
Five pets, each named after the noise it makes: MOOO (a cow with a long moo), BOO (a ghost), MEOW, MOO and BAA. A dictionary puts them in the order BAA, BOO, MEOW, MOO, MOOO.

  
MOOO has 4 letters. BOO, MOO and BAA have only three. Two questions come before any buckets.


  

    
Check yourself — 7 of 8

    
Every name needs 4 letters, like MOOO. Where does MOO get its blank?

    

      
      
      
    

    
At the end, before A. Putting MOO last would put it after MOOO. A dictionary puts MOO first.

  


  

    
Why the blank goes at the end

    
A dictionary compares names from the first letter, so the first letters must line up. A blank at the beginning lines up the last letters instead:

    

      

        At the beginning

        At the end

      

    

    
The blank comes before A because a shorter name comes first when the rest is the same: MOO before MOOO.

  


  

  
Now every name has 4 letters, so there are 4 passes, one for each letter.


  

    
Check yourself — 8 of 8

    
Which letter does pass 1 read?

    

      
      
      
    

    
Letter 4, on the right, like the units digit. Starting at each name’s own last letter is the same as a blank at the beginning. The box above showed where that goes wrong: MOO before MEOW.

  


  

    
Why start on the right

    
As in Section 5, the last pass decides. Here is the same sort both ways:

    

      

        Letter 1 first

        Letter 4 first

      

    

    
Letter 1 first ends on letter 4. W comes after O, so MEOW ends up last. Letter 4 first ends on letter 1, the letter a dictionary reads first.

Question and answer
Which sort for each scenario

  

    
FinalSpring 2026 · Q3 (b)3 marks

    
Analyze and identify the most optimal sorting algorithm for each of the following scenarios, providing a concise justification based on performance efficiency: (i) Processing a stream of nearly-sorted data where elements arrive sequentially with minimal inversions (ii) Sorting a large integer dataset restricted to a very small range (e.g., ages 1–100) (iii) Sorting a massive dataset in a memory-constrained environment where a guaranteed O(n log n) worst-case time complexity is required without using extra space.

  

  
(i) Insertion sort. Its cost is about n plus the number of out-of-order pairs, so on nearly sorted data it is close to O(n). It inserts each value as it arrives.

  
(ii) Counting sort. The range is small (k = 100), so O(n + k) = O(n), with no comparisons.

  
(iii) Heap sort. Guaranteed O(n log n) in the worst case, and it sorts in place. Taught in Trees & Heaps.
