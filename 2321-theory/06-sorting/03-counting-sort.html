Section 1

Sorting without comparing

⏱ 5 min

Every sort so far decides by comparing two values. Bubble, selection and insertion sort all do it.

Your turn

You have the ages of 1,000 students. Every age is 17, 18, 19 or 20. Can you sort them without comparing any two?

Hint: how many different ages can there be?

Yes. There are only 4 possible ages. Keep 4 tallies. Read each age once and add one to its tally. Then write 17 as many times as its tally says, then 18, then 19, then 20.

That is counting sort. It works when the values are whole numbers in a small, known range.

Section 3

The plain code

⏱ 9 min

Two loops do all the work.

  • Count: for each key in A, add one to COUNT[key].
  • Write back: for each value v from 0 to K − 1, write v into a, count[v] times.

Watch two variables. pos points at the next cell of a to fill. c says how many more copies of v are left to write.

Step 2 turned the counts 2, 4, 3, 1 into 2, 6, 9, 10. COUNT[V] then says how many numbers have a key ≤ V. That is the last slot of V’s group.


  

    
Check yourself — 3 of 5

    
After the running totals, COUNT[1] = 6. What does that mean?

    

      
      
      
    

    
The last 1-ender goes in slot 6. Six numbers end in 0 or 1, so the 1-enders end at slot 6. There are four of them, so they fill slots 3 to 6.

  


  

    
Your turn

    

      
Why read A backwards in Step 3?

      
Hint: COUNT[1] = 6 is the last 1-slot. Which of 41, 11, 81, 21 should get it?

    

    
    

      
21, the last 1-ender in the input. Reading backwards gives the last slot to the last number. So 41, 11, 81, 21 come out in their input order.

    

  


  

    
Check yourself — 4 of 5

    
Keep the running totals, but read A forwards (I = 1 to N). What happens?

    

      
      
      
    

    
Equal keys come out reversed. 41 would take slot 6, the last 1-slot, so the 1-enders read 21 81 11 41. The keys are still in order; stability is lost.

Why b starts at b[1]

    
count[d] is a slot number, from 1 to n. So b gets one extra cell, and the code uses b[1] to b[n]. b[0] is never used. Then slot count[d] is simply b[count[d]], the same as B[COUNT[D]] in the exam notation.

Section 7
What it costs, and when to use it

    ⏱ 5 min
  


  
The loops run n times (the keys) and k times (the counts). Nothing runs n × n times.


  

    
Time
O(n + k)

    
Space
O(n + k)

    
n is the number of keys; k is the range of keys. The stable version needs B (n cells) and COUNT (k cells).

  


  

    
Your turn

    

      
Would you use counting sort on 10 numbers, each up to 1,000,000,000?

    

    
    

      
No. COUNT would need a billion cells for just ten values. k is huge, so O(n + k) is huge. Next class, radix sort fixes this.

    

  


  

  

    
FinalSpring 2026 · Q3 (b) (ii)part of 3 marks

    
Analyze and identify the most optimal sorting algorithm for each of the following scenarios … Sorting a large integer dataset restricted to a very small range (e.g., ages 1–100)

  


  

    
The answer to write

    
Counting sort. The range is small (k = 100), so it runs in O(n + 100) = O(n) time. It needs no comparisons.

  


  

    
Check yourself — 5 of 5

    
How much extra space does stable counting sort use?

    

      
      
      
    

    
O(n + k): B holds n numbers and COUNT holds k counts. This is the price for never comparing.

Question and answer
Which sort for each scenario

  

    
FinalSpring 2026 · Q3 (b)3 marks

    
Analyze and identify the most optimal sorting algorithm for each of the following scenarios, providing a concise justification based on performance efficiency: (i) Processing a stream of nearly-sorted data where elements arrive sequentially with minimal inversions (ii) Sorting a large integer dataset restricted to a very small range (e.g., ages 1–100) (iii) Sorting a massive dataset in a memory-constrained environment where a guaranteed O(n log n) worst-case time complexity is required without using extra space.

  

  
(i) Insertion sort. It costs about n plus the number of out-of-order pairs, so on nearly sorted data it is close to O(n). It inserts each value as it arrives.

  
(ii) Counting sort. The range is small (k = 100), so it runs in O(n + k) = O(n), with no comparisons.

  
(iii) Heap sort. It guarantees O(n log n) in the worst case and sorts in place. Heap sort is taught in Trees & Heaps.






  
Question and answer
Stability

  

    
FinalSpring 2023 · Q3 (b)1 mark

    
Which of the following is not a stable sorting algorithm in its typical implementation: i) Insertion Sort ii) Merge Sort iii) Quick Sort iv) Bubble Sort

  

  
iii) Quick Sort. Insertion sort and bubble sort are stable: they never move a value past an equal one. Merge sort is stable too. Quicksort and merge sort are taught in CSE-2421.

  
Stable means equal keys come out in the order they went in. Counting sort is stable when it uses running totals and fills from the back, as in Sections 6 and 7.
