"Aren't entity set and file the same thing?"

Almost — and this is exactly where students lose the mark. There are two parallel vocabularies. One describes the real world. The other describes how we store it. They match one-to-one, but they are not the same words.

The clean way to say it in an exam

"The entity is a student. Its attributes are Name, ID Number, Section, Total Marks and Final Grade. The entity set is all the students in the class.

When that entity set is stored in a computer, each attribute becomes a field, each entity becomes a record, and the whole set becomes a file."

Entity set is the students. File is the data about the students. Two views of the same thing — one outside the computer, one inside it.

Part (ii) — which attribute is the primary key?

ID Number. A key is a field whose values uniquely identify a record.

Two students can share a name. Many share a section, a mark, or a grade. No two share an ID number — that is the whole reason the university gives them one.

In the Spring 2023 library version, the answer is ISBN — for exactly the same reason.

Why we started here

A file is a collection of records. A record is a collection of fields. A data structure is just a decision about how to hold that collection.

Keep the records in a row → an array. Join them with pointers → a linked list. Sort them by key → a tree. Jump straight to a record from its key → a hash table. Same records every time. Different box.

Quick check
In the class list above, what is "B" in the Section column of the third row?
The value of one field, for one record. The field is the Section column. The record is Tanvir Hasan's whole row. The entity is Tanvir himself. "B" is just the value sitting where that field and that record cross.

Data items: group and elementary

⏱ 6 min

Definition

A data item refers to a single unit of values.

Data items that are divided into sub-items are called group items.
Those that are not divided are called elementary items.

The textbook example: a student's name may be divided into three sub-items — first name, middle name and last name. But the student's roll number is normally treated as a single item.

Section 3

Data type: built-in and abstract

⏱ 7 min

Definition

A data type is a term which refers to the kind of data that may appear in a computation.

Built-in data type

Every programming language comes with a set of data types already made. You did not build them.

In C, the built-in types are:

int   float   char   double

Abstract data type (user-defined)

When an application needs a special kind of data that is not available as a built-in type, it becomes the programmer's job to build it.

This programmer's own type is called an abstract data type, or a user-defined data type.

The textbook example

We want to process dates of the form dd/mm/yy.

There is no built-in type for this in C. So if a programmer wants to process dates, an abstract data type — say Date — can be implemented.

In C and C++, programmers define their own data types using struct or class.

// C has int, float, char, double. It has no Date.
// So we build one.
struct Date {
    int day;
    int month;
    int year;
};

The rule to remember

An abstract data type is built with the help of built-in data types, and other abstract data types the programmer has already built.

That is how every big program is made: small boxes inside bigger boxes. A Student holds a Date, which holds three ints.

Section 5 · the most important idea today

ADT — Abstract Data Type

⏱ 10 min

Definition — learn this word for word

An Abstract Data Type (ADT) is a type (or class) for objects whose behaviour is defined by a set of values and a set of operations.

It only mentions what operations are to be performed, not how they will be implemented. It does not say how the data is organised in memory, or which algorithms are used.

Why "abstract"?

Because it gives an implementation-independent view. You can use it without knowing how it was built.

What is abstraction?

Providing only the essentials and hiding the details is called abstraction.

You have already used one — vector

You wrote this in Programming 1 and never thought twice about it:

vector<int> v;
v.push_back(10);
v.push_back(20);
cout << v[0] << " " << v.size();

Now answer three questions about that code. How big is the array inside? What happens when it fills up? Where in memory does it live?

You do not know any of them — and your program worked perfectly anyway. That is abstraction doing its job.

What is actually happening inside

vector holds a plain fixed-size array. When you push_back into a full one, it quietly allocates a bigger array, copies everything across, and frees the old one. You were never told, and you never needed to be.

ADT and class — how they relate

An ADT is an idea. A class is the language feature you write the idea down with. They line up exactly:

In the ADTIn a C++ class
The set of operations — what you may dopublic:
The hidden implementation — how it is doneprivate:
The set of values it holdsthe private data members
 
class Stack {
private:                  // ← the part the ADT HIDES
    int data[100];
    int top = -1;

public:                   // ← the part the ADT PROMISES
    void push(int x);
    void pop();
    int  top();
    bool empty();
};

The relationship in one line

The ADT is the contract. The class is one way of signing it.

Change everything under private — swap the array for a linked list — and every program that uses your Stack keeps compiling and keeps working.

The sentence that connects this to Class 1

The ADT is the job. The data structure is the box you do the job in.

"Stack" tells you push and pop exist. It says nothing about whether it is fast. The hidden choice is where speed lives — and that hidden choice is what made 3 billion into 9.

Dig deeper

?If the ADT hides everything, how do I know which one is faster?
You read the documentation, or you look at the implementation. The ADT hides the details from your code, not from your brain.

This is exactly why you are taking this course. Anyone can call push(). Knowing whether it is O(1) or O(n), and what it costs in memory, is the difference between a programmer and an engineer.
?Is an ADT the same thing as a class?
Closely related, not identical. A class is a language feature. An ADT is an idea that existed long before C++.

A class is the most convenient way to implement an ADT. But you can implement one in plain C with a struct and some functions — and you can write a class that is not an ADT at all, if it makes all its internals public and hides nothing.

Short version: ADT is the contract, class is one tool for writing it down.
?Further reading — writing the Stack ADT out in full
An ADT is written as a contract before any code exists. For a Stack it reads like this:

Values: an ordered collection of items, all of the same type.
Operations:
push(x) — add x to the top. Fails if the stack is full.
pop() — remove and return the top item. Fails if empty (underflow).
top() — return the top item without removing it.
empty() — true when there are no items.
size() — how many items are held.

The rule that makes it a stack: the item returned by pop() is always the one most recently given to push(). That single sentence is LIFO, and it is the only promise the ADT makes.

Notice what is not here: no array, no size limit, no memory, no algorithm. Two programmers could read this contract and build completely different stacks — and every program using either one would behave identically. That is the point of writing it this way.

You will write exactly this contract for real in Segment 4.
?Real example where the hidden choice mattered — map vs unordered_map
Both are the same ADT — a map: store key→value, look up by key. Nearly identical code.

map is built on a red-black tree: lookup O(log n), keys stay sorted.
unordered_map is built on a hash table: lookup O(1) on average, no order at all.

Same operations, very different behaviour. Both are on our syllabus — Segment 9 and Segment 10.
Quick check
You change a class's private array into a linked list. What must change in the programs that use it?
Nothing. That is the whole payoff of an ADT. The public operations are the contract; private is free to change. Speed and memory will change — so measure — but not one line of calling code has to be rewritten.

So what is a data structure?

⏱ 10 min

A data structure is two things together

1. A way of organising data in memory.     2. The set of operations you are allowed to perform on it.

They split into two families. Here is what each one actually looks like — and for the stack and the queue, press "real life" to see where the idea came from.

Linear — everything in a line

Each element has one before it and one after it.

Non-linear — one thing connects to many

There is no single "next". Following the links, you have choices.

Notice what just happened

Every definition above said what you can do. Not one said how it is built.

That is deliberate. Learn the behaviour first. The machinery comes in Segment 2 through Segment 9.

Section 8 · the idea behind the whole course

Time–space tradeoff

⏱ 9 min

The idea in one line

You can make a program faster by using more memory, or use less memory by accepting more work. You usually cannot have both.

The smallest possible example: swap two variables

You have a = 5 and b = 9. You want them exchanged. There are two well-known ways, and they sit on opposite sides of the trade.

Way 1 — with a temp variable

int temp = a;
a = b;
b = temp;

There it is, in three lines of code

Way 1 costs 1 extra variable but only 3 operations.
Way 2 costs 0 extra variables but 6 operations.

Neither is free. You chose what to pay with — space or time. That is the time–space tradeoff, and it is the same decision you will make with every structure this semester, just bigger.

⚠ And still — do not actually use Way 2

It is a famous interview question. Knowing it is useful. Using it is not:

1. It is slower. Six operations instead of three, to save one variable that costs almost nothing.
2. Overflow. a + b can exceed the range of an int even when a and b are both fine alone.
3. It breaks when a and b are the same variable. swap(x, x) sets x to zero — x + x, then x − x = 0.

The real lesson: the trade was not worth making. Knowing when not to trade is as important as knowing the trade exists.

📌

Ask this every single time something gets faster in this course.

"What did I pay?" The answer is almost always memory. Trie? More memory. Hash table? More memory. The extra pointer in a doubly linked list? More memory.

There is no free speed. Say it back to me in week 15.

Dig deeper

?Would the compiler optimise Way 2 for me?
Usually the opposite — the compiler optimises Way 1.

A temp variable normally never reaches RAM at all. It lives in a CPU register, and a good compiler often turns the whole thing into a single machine instruction (XCHG) or just renames the registers and emits no instructions at all.

Way 2 gives the compiler three real arithmetic dependencies it cannot skip. The "clever" version is the one that ends up slower.

The general lesson: do not out-clever the compiler on tiny things. Save your cleverness for choosing the right data structure — that is a decision no compiler can make for you.
?Is there a swap trick that at least cannot overflow?
Yes — the XOR swap: a ^= b; b ^= a; a ^= b; No extra variable, and no overflow, because XOR only flips bits.

But it keeps the fatal flaw: if a and b are the same variable, it sets it to zero. And it is still 6 operations, still not faster.

In real C++ you write std::swap(a, b); and let the library and the compiler pick the fastest thing.
?Can a tradeoff ever go the other way — spend time to save memory?
Absolutely, and it is common when memory is the scarce resource.

Compression is the clearest case: a zipped file takes far less disk, but you pay CPU time every time you open it. Recomputing instead of storing is another — if a value is cheap to calculate and huge to keep, throw it away and compute it again.

The trade runs both directions. The engineering skill is knowing which resource is actually scarce in your situation.
?Where else will I meet this exact tradeoff this semester?
Everywhere. Keep a list as we go:

Doubly linked list Seg 3 — one extra pointer per node buys backwards traversal.
Counting sort Seg 6 — an extra array the size of the value range buys O(n) sorting.
Hash table Seg 10 — a table bigger than your data buys O(1) lookup.
Trie Seg 9 — a node per character buys prefix search that ignores dataset size.

Every one of them is the swap example again, with bigger numbers.
Quick check
You add an index to a database table and queries get 100× faster. What did you pay?
Extra disk space, and slower inserts. The index is a whole extra data structure (a B-tree) stored beside your table — that is the space. And every new row must now be added to the table and the index — that is the time. Reads got faster; writes got slower. You will meet this again in your DBMS course.

?Entities, attributes, entity set, primary key — Spring 2024 & Spring 2023 [2 marks]
Spring 2024, Q1(a): "A professor keeps a class list containing the following data for each student: Name, ID Number, Section, Total Marks, Final Grade. (i) State the entities, attributes and entity set of the list. (ii) Which attribute can serve as the primary key for the list?"

Spring 2023, Q1(a): the same question about a library book list — Name of Authors, Title of Book, Edition, Publisher's Name, Year, ISBN.

Model answer — the class list

Entity: a student. Each student is one thing with properties that can be given values.
Attributes: Name, ID Number, Section, Total Marks, Final Grade.
Entity set: all the students in the professor's class — the entities sharing those same attributes.
Primary key: ID Number, because its value is unique for every student. Names can repeat; sections, marks and grades repeat constantly. Only the ID identifies exactly one record.

Model answer — the book list

Entity: a book.  Attributes: Name of Authors, Title, Edition, Publisher's Name, Year, ISBN.
Entity set: all the books in the library.  Primary key: ISBN — every book has a different one, while titles, publishers and years repeat.

⚠ Where the mark is lost: writing "the entity is the class list". The list is the entity set. One student is the entity.

?What is a data structure? Describe the operations — Spring 2025 [2 marks]
Spring 2025, Q1(a): "What do you mean by a data structure? Briefly describe the different operations performed on data structures."

Model answer. A data structure is a way of organising data in memory, together with the set of operations that may be performed on it. The operations are:

Traverse — access each element exactly once so it can be processed.
Search — find the location of the element with a given key.
Insert — add a new element to the structure.
Delete — remove an element from the structure.
Update — change the value of an existing element.
Sort — arrange the elements in some logical order.
Merge — combine two sorted sets of elements into a single sorted set.

Two marks for seven operations means one line each. Do not write paragraphs — write the list.
?Space complexity of a swap function — Spring 2024 & Spring 2023 [2 marks]
Spring 2024, Q1(c): "What do you mean by space complexity? What is the space complexity of the following functions? Explain."

void swap()
{
    int a, b, temp;
    temp = a;
    a = b;
    b = temp;
}
Model answer. Space complexity is the total memory an algorithm needs to run, measured as a function of the input size.

This function uses three integer variables and nothing more. That number does not grow when the input grows — it is fixed. So the space complexity is O(1), also called constant space.

Say this and you secure the mark: "the temp variable is extra space, but it is a fixed amount of extra space, so it is still O(1) — not O(n)."

The identical question appears on the Spring 2023 paper. This is the swap from Section 8.
?Array vs linked list — Autumn 2025 & Spring 2025 [2 marks]
Autumn 2025, Q3(a): "What is the difference between Array and Linked List? Which one is better for searching an element and why?"

Spring 2025, Q3(a): "What is linked list? What is the difference between an array and a linked list in terms of their memory structure and operations? Which one is more efficient for searching an element, and why?"

Model answer.
Memory: an array occupies one continuous block of memory; a linked list uses separate nodes anywhere in memory, joined by pointers.
Access: an array reaches any position in O(1) by calculating base + i × size. A linked list must walk from the head — O(n).
Insert / delete: in the middle of an array everything after the position must shift — O(n). In a linked list it is O(1) once you already hold that node.
Size: an array is fixed; a linked list grows as needed.

Which is better for searching? The array — because binary search needs random access, which only the array has. On a sorted array searching is O(log n); on a linked list you are stuck with O(n) no matter what.

Interview questions

Asked constantly, at every level

?What is an abstract data type? Give an example from a language you use.
Give the definition, then immediately give a real example — that is what separates a good answer.

"An ADT defines what operations exist without saying how they work. C++'s std::stack is an ADT — I get push, pop and top. I never see whether it uses an array or a list underneath, and my code does not care."

Then add the killer line: "which means I can swap the implementation for a faster one without changing a single line of code that uses it."

Segment 1
?What is the difference between an ADT and a data structure?
ADT is the specification. Data structure is the implementation.

"Stack" is an ADT — a promise that push and pop exist and behave LIFO. An array-based stack and a linked-list-based stack are two different data structures that both keep that promise.

Analogy that works well: the ADT is the contract; the data structure is the building you actually put up to satisfy it.

Segment 1
?Explain the time–space tradeoff with something you have actually done.
Interviewers ask this to see whether you think about cost at all. Do not give the textbook answer — give a concrete one:

"I was checking for duplicates in a large array. The nested loop needed no extra memory but was O(n²). I used a hash set instead — O(n) time, but now I am storing every element a second time. I spent memory to buy speed."

Then show judgement: "if memory had been tight and n small, I would have kept the loop." Knowing when not to optimise is what they are really testing.

Segment 1 Segment 10
?What are the different types of data structure?
This exact question appears in the interview transcript from Class 1. Answer in a structure, not a list:

Linear — elements in a sequence: array, linked list, stack, queue.
Non-linear — one element connects to many: tree, graph, trie.

Then earn the follow-up: "and within linear, the real split is whether memory is contiguous (array — fast access, slow insert) or linked (linked list — slow access, fast insert). That choice decides everything else."

Segment 1 Segment 2 Segment 3
?Why do we need data structures at all? Why not use an array for everything?
An array is excellent at exactly one thing — reading position i instantly. It is bad at almost everything else: inserting in the middle is O(n), searching an unsorted array is O(n), and it has a fixed size.

Every other structure exists because somebody needed one of those to be fast:
fast insert anywhere → linked list · fast lookup by key → hash table · largest item fast → heap · sorted order and fast lookup → balanced tree · prefix search → trie.

The one-line answer: "different structures make different operations cheap, and you pick the one whose cheap operations are the ones you do most."
