Story three · Wow

You search "Hero Alam" on Facebook.

⏱ 12 min

Facebook has about 3 billion users. That is 3,000,000,000 names.

You type Hero Alam in the search box. Facebook must find that name among 3 billion names.

The normal way

This is the way every one of you would write it tomorrow. Check every name, one by one:

for each of the 3,000,000,000 users:
    if user.name starts with "Hero Alam":
        show this user

Simple. Correct. It works.

Our assumption for every number today

A normal computer does about 100,000,000 operations per second — that is 108. This is the number we will use all semester.

Dig deeper — the questions sharp students ask

?Does Facebook really use a trie?
Honestly — not a plain trie on its own. Real search at that scale uses a distributed inverted index, with prefix structures and tries inside it, plus caching and thousands of machines.

But every one of those is a data structure. The example here is simplified down to one. The 300-million-times gap is real — it is exactly why nobody builds search with a loop.
?Why 108 operations per second? Where does that number come from?
It is the standard working figure used in competitive programming and in this course: a normal machine gets through roughly 108 simple operations every second.

It is deliberately a round number, not a measurement. A tight loop of additions can beat it; comparing strings scattered across memory is slower than it. So the estimate is already generous to the slow method — in real life, checking 3 billion names takes longer than 30 seconds, not shorter.

Use 108 all semester. When you are told a Codeforces problem has n = 105 and a 1-second limit, that number tells you instantly whether an O(n²) solution can pass. It cannot: 1010 operations would need about 100 seconds.
?Can't Facebook just use more servers?
This is the best question you can ask today. Yes — 10,000 servers turns 347 days into about 50 minutes.

But: it is still far too slow (you expect results in under a second), and now you are paying for 10,000 servers. The trie does it on one machine in 9 milliseconds.

The lesson: hardware buys you a constant. A better data structure changes the shape of the problem. Money runs out. Better thinking does not.
?If a trie is so fast, why not use it for everything?
Because it is expensive in memory. A trie stores a node for every letter of every name, with links out of each node. For 3 billion names that is an enormous amount of RAM — far more than a plain list of names would need.

This is called the time–space tradeoff, and it is the single most important idea in this whole course. You almost never get speed for free. You buy it with memory.

Every fast structure you learn this semester — trie, hash table, heap — is you spending memory to buy time.
?What actually IS a trie?
Picture a tree where every edge is a letter. To store "Hero", you walk H → e → r → o, creating nodes as you go. To store "Hero Alam", you continue from the same "Hero" path.

Now searching is not "compare against every name". It is "follow the letters I typed". Nine letters, nine steps down the tree — and the tree does not care whether it holds 100 names or 3 billion.

That is the whole idea. We build it properly in Segment 9.
Quick check
Facebook adds 1 billion new users. What happens to the trie search for "Hero Alam"?
Correct: nothing changes. The trie walks one step for each letter you typed. "Hero Alam" has 9 letters today and it will have 9 letters after Facebook doubles in size. The number of users never enters the calculation. That is the whole idea, and it is why this course exists.

Dig deeper

?Which language should I use?
C++. Not because the others are bad, but because of three practical reasons for you specifically:

it is what your course and exams use · it is fast enough that a correct solution never fails for being slow · and its standard library (vector, map, set, stack, queue, priority_queue) is exactly the list of structures we study this semester, so the language teaches you the syllabus while you use it.

If you are already fluent in Java or Python, use it for now — but be ready to move to C++ by Segment 4.
?What does "Wrong Answer on test 7" actually mean?
The judge runs your program against a set of hidden tests. Test 7 is one of them, and your output did not match. It almost always means one of three things:

1. an edge case you did not think about (n = 1, an empty input, all numbers the same) · 2. a number too big for the type you used · 3. you solved a slightly different problem than the one written.

It is not the judge being unfair. It is the most honest feedback you will get all semester.
?How many problems should I solve to be interview ready?
There is no magic number, but a useful target: around 150–200 problems solved properly over these two semesters, weighted toward easy and medium.

"Properly" is doing the work. Ten problems you solved yourself after struggling beat a hundred you read the solution to. If you looked at an answer, close it, wait two days, and solve it again from a blank file. If you cannot, you did not learn it.

The interview

Questions that come up again and again

Only the questions this class actually answers. The technical questions from the transcript — heaps, BSTs, traversals, sorting — belong to the classes that teach them, and you will find them there.

?Why do we need data structures at all? Why not just use an array for everything?
This is the question this whole class answers, and it does get asked directly.

An array is excellent at exactly one thing — reading position i instantly. It is poor at almost everything else: inserting in the middle is O(n), searching an unsorted array is O(n), and its size is fixed.

Every other structure exists because somebody needed one of those to be fast:
fast insert anywhere → linked list · fast lookup by key → hash table · largest item fast → heap · sorted order and fast lookup → balanced tree · prefix search → trie.

The one-line answer: "different structures make different operations cheap, and you pick the one whose cheap operations are the ones you do most."

Segment 1
?Why does every answer need a time and space complexity?
Because "it works" is not an answer in this field. Two programs that both work can differ by a factor of 333 million — you saw that in Story 3.

When you say "this is O(n log n) time and O(1) extra space", you are telling the interviewer three things at once: you know what your code costs, you know there are alternatives, and you can compare them. That is the whole job.

The candidate in Story 2 wrote it down as the single most important note of his interview: time & space complexity answer must.

Build the habit now. Every problem you solve on Codeforces this semester — say the complexity out loud before you submit.

Segment 1

💡 How to answer any of these

1. Say what it is in one sentence. 2. Give the real-life picture. 3. State the complexity. 4. Say when you would not use it.

Step 4 is what separates a good answer from a memorised one. Anyone can recite what a heap is. Saying "but if I only need the maximum once, sorting is simpler and I would not build a heap at all" is what gets you hired.
