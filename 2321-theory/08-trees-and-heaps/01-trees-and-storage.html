Section 3

The binary tree, defined

⏱ 8 min

Lipschutz's definition

A binary tree T is a finite set of nodes such that either T is empty (the null tree), or T has a root R and the other nodes form an ordered pair of binary trees, the left subtree and the right subtree of R.

The definition uses itself, as a recursive function does. The empty tree is its base case. In the drawings below, an empty subtree is a cut stump.

Your turn

The two trees below hold the same two letters. Are they the same binary tree?

No. In the first, B is the left child of A. In the second, B is the right child. The pair is ordered, so the two are different binary trees.

Section 4

Full, complete, 2-tree

⏱ 10 min

Level r of a binary tree holds at most 2r nodes: 1, then 2, then 4, then 8.

  • Full: every level holds as many nodes as it can. A full tree of depth d has 2d − 1 nodes.
  • Complete: every level is full except perhaps the last, and the last level fills from the left.
  • 2-tree (extended binary tree): every node has 0 or 2 children. A node with two is internal; a node with none is external.
Your turn

i

The dashed circles are positions the tree could fill, numbered level by level, left to right. A tree is complete exactly when its nodes sit in positions 1 to n with no gap. Section 6 uses those numbers.

⚠ A sentence to correct in some notes

Some notes say a full tree of height h "has all its leaves at level h". Levels start at 0, so the leaves sit at level h − 1. They also say "all non-leaf nodes have two children": that is the 2-tree, not the full tree.

Section 5

Stored with links

⏱ 10 min

You already know a linked-list node: data and one link. A tree node is the same, with two links. Lipschutz stores it in three parallel arrays:

  • INFO[K] holds the data at node K.
  • LEFT[K] holds where its left child is, and RIGHT[K] where its right child is.
  • ROOT holds where the root is. A null link means that subtree is empty.

Here is Fig 7.1 drawn the way the book draws it (Fig 7.6): every node in three parts, LEFT, INFO, RIGHT, with ✕ for null.

The page to keep

    ⏱ 4 min
  


  

    

      
The words

      
    
        
  • Root: the top node. Leaf (terminal node): no children.
    • 
        
  • Parent, child, sibling; ancestor, descendant.
    • 
        
  • Edge: a line to a child. Path: edges in a row. Branch: a path ending in a leaf.
    • 
        
  • Level: the root is 0. Depth: nodes on the longest branch = largest level + 1.
    • 
      

    

    

      
Three kinds of tree

      
    
        
  • Full: every level full; 2d − 1 nodes.
    • 
        
  • Complete: full except the last level, which fills from the left.
    • 
        
  • 2-tree: every node has 0 or 2 children.
    • 
      

    

    

      
Two ways to store one

      
    
        
  • Links: INFO, LEFT, RIGHT, and ROOT. Null = empty subtree.
    • 
        
  • Array: root at TREE[1]; children of TREE[K] at 2K and 2K + 1; parent at ⌊K/2⌋.
    • 
      

    

  


  
?Why do computer scientists draw trees upside down?
    
Because we read from the top. The root is where every search starts, so it goes first, where the eye starts. So the chart of a tree is upside down compared with a real one: root at the top, leaves at the bottom. Look at the pond in the picture at the top of this page.

Question and answer
Binary tree vs complete binary tree

  

    
FinalAutumn 2024 · Q4 (a)5 marks, with (b) part

    
Analyze the differences between Binary tree and Complete binary tree with figure.

  

  
Binary tree. A binary tree T is a finite set of nodes which is either empty, or has a root R whose remaining nodes form an ordered pair of disjoint binary trees, the left and right subtrees of R. Each node has at most two children.

  
Complete binary tree. A binary tree is complete if all its levels, except possibly the last, have the maximum number of nodes, and all the nodes at the last level appear as far left as possible.

  

  
Left: a binary tree that is not complete (Fig 7.1). Right: a complete binary tree with 10 nodes.

  

    
Binary treeComplete binary tree

    
ShapeAny shape; at most two children a nodeEvery level full except the last, which fills from the left

    
Array storageCan leave gaps in TREE[]Fills TREE[1..n] with no gaps

    
Depth for n nodesAnything from ⌊log₂ n⌋ + 1 up to nAlways ⌊log₂ n⌋ + 1

    
How many of themMany shapes for one nExactly one shape for each n

  






  
Model answer
Full, complete and 2-tree

  
    
    
  • Full binary tree: every level has the maximum number of nodes. A full tree of depth d has 2d − 1 nodes, and its leaves are all on level d − 1.
    • 
    
  • Complete binary tree: every level is full except possibly the last, whose nodes are as far left as possible.
    • 
    
  • Extended binary tree, or 2-tree: every node has either 0 or 2 children. The nodes with two children are internal nodes; those with none are external nodes.
    • 
  

  
Every full tree is complete. A complete tree need not be full. A 2-tree need not be complete.
