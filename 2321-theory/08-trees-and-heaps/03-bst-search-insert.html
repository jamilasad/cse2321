Smaller keys to the left, larger keys to the right, at every node. Then a search walks one path down from the root. An insert is a search that ended on an empty branch.

Watch it find

⏱ 6 min

Segment 2's binary search finds a key in a sorted array in about log₂ n looks. Putting a new key into that array is the slow part: every key after its slot moves one place.

A binary search tree keeps the halving and drops the moving. Here is Lipschutz's Fig 7.21. Watch the key 20 look for its place.

Four comparisons, and no other key moved. In a sorted array of the same nine keys, the six keys larger than 20 would each have moved one place.

Your turn

In this tree, which nodes does a search for 60 visit?

40, 70, 60. 60 is larger than 40, so go right. 60 is smaller than 70, so go left. Then 60 itself. The left half of the tree is never looked at.

Section 2

The rule

⏱ 8 min

This is Lipschutz's definition. Write it when an exam asks "What is a BST?"

Binary search tree · Lipschutz 7.24

Suppose T is a binary tree. Then T is called a binary search tree (or binary sorted tree) if each node N of T has the following property: The value at N is greater than every value in the left subtree of N and is less than every value in the right subtree of N.

Every value in the subtree, not just the child. That is the half students drop. The values are also all different; Section 7 deals with a repeat.

Your turn

In Fig 7.21, replace 23 by 35. Is it still a BST? Now replace it by 40.

Yes with 35. No with 40. 40 sits in 38's left subtree, and 38 must be greater than everything there. Every node near 40 is happy; only 38, two levels up, is broken. This is Lipschutz's Example 7.13.

Explorer Change one key

i

The row under the tree is the inorder walk. In a BST it always comes out sorted: the left subtree is all smaller, then the node, then the right subtree, all larger, at every node. So an inorder walk is a test you can run on any tree.

The deck's slide says "less than or equal to" on the right. That is the book's second definition, which allows repeated keys. This course uses the first one.

Check yourself — 1 of 4
What does the inorder walk of any BST give?
Sorted. At every node, inorder writes the left subtree first (all smaller), then the node, then the right subtree (all larger).

A tree from a preorder

    ⏱ 12 min
  


  
Five finals give a BST's preorder and ask for the tree. There is nothing new to learn: insert the keys in the order given.

  
It works because preorder writes every node before its children. So each parent is already in the tree when its child arrives, and the child walks down to the place it came from.

Worst

Keys in a random order give a bushy tree: Lipschutz puts an average search at about 1.4 log₂ n comparisons. Keys that arrive sorted, rising or falling, give a chain of depth n.

  

  
That is Spring 2026 Q4 (b) in full: why the average is O(log n), why the worst is O(n), and when the worst happens. Week 14's AVL tree repairs its own shape after every insert, so even sorted keys stay O(log n).


  

    
Check yourself — 4 of 4

    
1000 keys are inserted in sorted order. At worst, how many comparisons does a search take?

    

      
      
      
    

    
1000. Sorted keys make a chain, one key per level. 10 is log₂ 1000, the depth of a perfectly bushy tree. 14 is about 1.4 log₂ 1000, the average for keys in a random order.

The other definition

    
The book's second definition (the deck's "less than or equal to" on the right) adds the second A as the right child of the first: 10 nodes. If a question names that definition, use it. Otherwise, a repeat is found and not added.

Question and answer
Average against worst

  

    
FinalSpring 2026 · Q4 (b)2 marks

    
Explain why the average time complexity for searching in a BST is O(log n), whereas the worst-case complexity is O(n). Under what specific condition does the worst-case scenario occur?

  

  
A search compares once per level, so it costs at most the depth of the tree. With keys inserted in a random order the tree stays bushy: its depth grows like log₂ n, and an average search takes about 1.4 log₂ n comparisons. So the average is O(log n).

  
If the keys are inserted in sorted order (rising or falling), each key goes to the same side of the last one. The tree is a chain of depth n, and a search may compare with every key: O(n).
