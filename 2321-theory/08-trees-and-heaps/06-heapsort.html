Section 1

Selection sort with a better finder

⏱ 6 min

You already know selection sort (Segment 6). Each pass looks at every key that is left to find the extreme one, then puts it in its place. On n keys that is n(n − 1)/2 comparisons.

You also know the heap (last class). Its largest key is always at the root. Taking it out and putting the heap right again walks one path: about log₂ n steps.

Your turn

Each pass of selection sort gets its key by a scan. Suppose each pass got its key from a heap instead. What would sorting n keys cost?

n passes × about log₂ n each = O(n log n). For a million keys that is about 20 million steps, against selection sort's 500 billion comparisons.

That sort is heapsort. Two things are left: where the heap comes from, and where each key goes when it leaves the top.

Section 2

Watch heapsort

⏱ 12 min

Lipschutz (§7.10) sorts in two phases:

Phase A. Build a heap H out of the elements of A.

Phase B. Repeatedly delete the root element of H.

Phase A is last class's build, one key at a time. Phase B is last class's delete, done again and again. Each delete takes out the largest key left, and the heap gets one box shorter.

Your turn

The heap lives in the array A. After a delete it is one box shorter. Where can the key that left go, without a second array?

Into the box the heap just gave up: the last one. The largest key goes to A[n], the next to A[n − 1], and so on. The sorted part grows from the right while the heap shrinks from the right.

Now watch it, on Autumn 2025's list, the one you built a heap from last class. The divider in the array is the heap's end.

Section 4
What it costs

    ⏱ 6 min
  


  
Phase A is n inserts. Phase B is n − 1 deletes. Each one walks a single path, and a complete tree of n nodes is only ⌊log₂ n⌋ + 1 levels deep. Lipschutz counts the comparisons: at most n log₂ n for Phase A and 4n log₂ n for Phase B.


  

    O(n log n)
    
Worst case included. No list can make a path longer than the tree is deep. And every key stays inside A the whole time: the sorted part is the end of the same array.

  


  

    
nSelection sort: n(n − 1)/2 comparisonsHeapsort: about n log₂ n

    
1,000499,500about 10,000

    
1,000,000about 500,000,000,000about 20,000,000

  


  
The exam sets heapsort against the other O(n log n) sorts. Merge sort is O(n log n), but it merges into a second array. Quicksort is O(n log n) on average, but O(n²) at worst. So when an exam asks for a guaranteed O(n log n) with no extra space, the answer is heapsort. That is Spring 2026 Q3 (b)(iii), word for word in the Exam tab.


  

    
Check yourself — 2 of 4

    
What is heapsort's running time in the worst case?

    

      
      
      
    

    
O(n log n). Each of the n inserts and n − 1 deletes walks one path of at most ⌊log₂ n⌋ + 1 levels, whatever the list. O(n²) is quicksort's worst case, and selection sort's every case.

Section 5
A faster build

    ⏱ 8 min
  


  
Inserting one key at a time builds a heap in O(n log n). There is a second way, used by every library and by the lab. It starts from the whole list already in the array.


  

    
Your turn

    

      
A leaf has no children. Is a one-node tree already a heap? Then which nodes of the array still need fixing, and in what order?

    

    
    

      
Yes: a leaf is a heap on its own. Only the parents need fixing. The last parent is TREE[⌊n/2⌋], because its child 2K must still be ≤ n. Go backwards from there to TREE[1], and sink each one, as delete sinks the last key. Going backwards means each parent sinks into two subtrees that are already heaps.

The priority queue, with a heap

    ⏱ 10 min
  


  
Segment 5's priority-queue page drew four passengers in a heap and said: "The heap row waits for the Trees & Heaps classes." This section fills that row.


  
One thing first. Segment 5 serves the smallest priority number first: a VVIP is 1. So its heap keeps the smallest key at the root, and every parent is ≤ its children. That is a min-heap. It is a max heap with one comparison turned round.


  

    
    
  

  
In insheap, if (item <= tree[par]) becomes if (item >= tree[par]). delheap turns its comparisons round the same way.


  
Push is INSHEAP and pop is DELHEAP, on a min-heap of priorities. Here are Segment 5's passengers again, in its four class colours.

One difference from Segment 5. Its rule 2 says equal priorities leave in arrival order. A heap does not remember who came first. Load the five boarding passengers and pop five times: they leave 13, 5, 3, 17, 33, not Segment 5's 13, 3, 5, 17, 33.

  
+Keeping arrival order
    

      
Give every push an arrival number, 0, 1, 2, …, and compare the pair (priority, arrival): a smaller priority wins, and between equal priorities the smaller arrival number wins. Then no two keys are ever equal, and the heap gives exactly Segment 5's order. Tick equal priorities by arrival above to see it. In C++ a heap is std::priority_queue. priority_queue<int> is a max heap. priority_queue<int, vector<int>, greater<int>> is a min-heap: greater<int> means the smallest is on top. Section 7 uses it.

  
Where it is used: a hospital's emergency room sees the most urgent patient first, and Segment 5's print server prints the most urgent job first. Both pay O(log n) a job when jobs arrive and leave at the same rate.

Section 7
The k largest

    ⏱ 10 min
  


  
Six finals ask this, in four wordings: the top 10 of a million items in a file, the top 5 salaries of 500,000 employees, the k largest, the 100 largest of 10⁵. The question is the same every time.


  

    
Your turn

    

      
You may keep only 3 keys. You hold 44, 30 and 50. Now 22 arrives, and then 60. Which of your three do you compare each newcomer with? So which of the kept keys must you be able to find fast?

    

    
    

      
The smallest of the three, 30. A newcomer gets in only if it beats the weakest key kept. 22 does not, so it is skipped. 60 does, so 30 goes and 60 comes in. The key you need fast is the smallest kept, and that is what a min-heap keeps at its root.

    

  


  
So keep a min-heap of size k, even though you want the largest. Each new key is compared with the root. Bigger: it replaces the root and sinks. Not bigger: it is skipped, after one comparison.

The hardest version: Spring 2026 Q4 (d)

  

    
FinalSpring 2026 · Q4 (d)3 marks

    
Given a dataset of N integers where N ≤ 10⁵, analyze the time and space complexity required to extract the 100 largest elements using two distinct approaches: constructing a Max-Heap of size N followed by 100 Extract-Max operations, versus maintaining a Min-Heap of size K = 100 while iterating through all N elements. Compare these strategies in terms of memory efficiency and execution time, justifying your analysis using Big-O notation.

  

  

    
    
  

  

    
(A) Max heap of N, 100 extracts(B) Min-heap of K = 100

    
TimeO(N + K log N): about 10⁵ + 100 × 17 ≈ 101,700 steps, with the O(N) bottom-up buildO(N log K): about 10⁵ × 6.6 ≈ 664,000 steps at worst

    
MemoryO(N): all 10⁵ keys heldO(K): 100 cells

  

  
The verdict. (B) wins on memory, and it is the only choice when the keys do not fit in memory (the "1 million items stored in file" wording of Autumn 2022–Autumn 2024). (A) can be faster, but only with Section 5's O(N) build: built by insertion it is about 1.66 million steps.

  
+Why 664,000 is the worst case, not the usual one
    
(B) pays log₂ 100 only when a key gets in. On a shuffled list, the i-th key is among the 100 largest so far with chance 100/i, so only about 690 of the 100,000 keys ever enter the heap. The rest lose to the root after one comparison. So in practice (B) is about 10⁵ steps too. The exam answer stays the Big-O one above.

Autumn 2022 Q4 (d): the top 10 largest items out of 1 million items stored in a file. Which data structure?

    

      
      
      
    

    
A min-heap of size 10. It holds 10 keys, not a million, and each key costs one comparison with the root, or O(log 10) if it gets in. A max heap needs the whole file in memory. A BST needs it too, and it degrades to a chain on sorted data.

Questions and answers
The k largest, in every wording

  

    
FinalAutumn 2022 · Q4 (d)1 mark

    
Explain which data structure is most efficient to find the top 10 largest items out of 1 million items stored in file? Why? i) Min heap ii) Max heap iii) BST iv) Sorted array

  

  
Autumn 2023 Q4 (c) and Autumn 2024 set the same top-10-of-a-million choice (the transcript summarises their wording).

  
Answer: i) a min-heap, of size 10. Keep the 10 largest seen so far. Each new item is compared with the root, the smallest of the 10. If it is bigger it replaces the root and sinks, in O(log 10); otherwise it is skipped. That is O(n log 10) time and only 10 cells of memory, so the million items can be read from the file one at a time. A max heap or a sorted array needs all million in memory (and sorting costs O(n log n)). A BST needs them all too, and degrades to O(n) a search on sorted data.

  

    
FinalSpring 2025 · Q4 (d)1 mark

    
To find the top 5 largest salaries from a dataset of 500K employees, which data structure is most efficient and why? i) Max heap ii) BST iii) Min heap iv) Sorted list

  

  
Answer: iii) a min-heap of size 5, for the same reason: 5 cells, one comparison with the root per salary, O(n log 5) in all.

  

    
FinalAutumn 2025 · Q4 (d)2 marks

    
Which heap (min or max) is used to find the k largest elements efficiently?

  

  
Answer: a min-heap of size k. Its root is the smallest of the k largest kept so far, so one comparison decides whether a new element gets in. O(n log k) time, O(k) space.

  

    
FinalSpring 2026 · Q4 (d)3 marks

    
Max-Heap of size N followed by 100 Extract-Max operations, versus a Min-Heap of size K = 100 while iterating through all N elements (N ≤ 10⁵): compare memory and time with Big-O.

  

  
    
    
  • (A) Max heap of N: build O(N) bottom-up, then 100 extracts at O(log N) each: O(N + K log N) time, about 101,700 steps. Memory O(N).
    • 
    
  • (B) Min-heap of K: each of N elements is compared with the root, and pays O(log K) if it gets in: O(N log K) time, about 664,000 steps at worst. Memory O(K).
    • 
    
  • Compare: (B) uses far less memory and works on a stream or a file; (A) can be faster in time when the data fits in memory and the O(N) build is used.

Questions and answers
Which sort?

  

    
FinalSpring 2026 · Q3 (b)(iii)part of 3 marks

    
A massive dataset in a memory-constrained environment where a guaranteed O(n log n) worst-case time complexity is required without using extra space.

  

  
Answer: heapsort. It is O(n log n) in the worst case (merge sort needs an O(n) second array; quicksort's worst case is O(n²)), and it sorts in place: the sorted part is the end of the same array.

  

    
FinalSpring 2025 · Q3 (b)1 mark

    
Which sorting algorithm would you recommend when swap operations are highly expensive? Justify based on: Heap Sort and Merge Sort [OR] Selection Sort and Quick Sort

  

  
Answer the [OR] pair: selection sort, which makes at most n − 1 swaps, one a pass (Segment 6). Between heapsort and merge sort neither is a clean answer: heapsort swaps O(n log n) times, and merge sort moves every element O(log n) times between two arrays.
