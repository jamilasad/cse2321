Section 1

A queue that lets some go first

⏱ 5 min

An ordinary queue has one rule: first in, first out. A priority queue gives every element one more piece of information — its priority — and serves by that first.

Definition

A priority queue is a collection of elements in which each element has a priority, and elements are deleted and processed by two rules:

  1. An element of higher priority is processed before any element of lower priority.
  2. Two elements with the same priority are processed in the order they were added.

The convention: a smaller number is a higher priority

Priorities are written as priority numbers. Priority 1 is served before priority 2. This is the textbook's convention and the exam's.

Boarding a plane

2CIPCommercially important person

Two operations

pop() — the next passenger boards. It takes no argument: the queue decides who.

A priority queue against an ordinary queue

    
Advantage: urgent elements do not wait behind earlier, less important ones. A VVIP does not queue behind 200 Normal passengers.

    
Disadvantages: every element must carry a priority; one operation now has to scan or walk, where an ordinary queue does both in O(1); and a low-priority element can wait forever if higher ones keep arriving.

  


  

    
The heap row

    
A job heavy on both ends wants neither of these.

    
The heap makes push and pop both O(log n). How it manages that is the job of the Trees & Heaps classes.

Model answers
What to write


  
What is a priority queue?

  
A collection of elements in which each element has a priority, processed by two rules: (1) an element of higher priority is processed before any element of lower priority; (2) two elements of the same priority are processed in the order they were added. A smaller priority number means a higher priority.


  
One-way list representation

  
Each node has three fields: INFO, PRN (priority number) and LINK — data, pr and next in our code. The list is sorted by PRN, and nodes with equal PRN are in the order they were added. The front of the queue is the first node.

  

    
Add ITEM with priority number M — O(n)

    
1. Traverse the list until finding a node X whose priority number is greater than M.

    
2. Insert ITEM in front of X. If no such node is found, insert ITEM as the last node.

    
3. Exit.

  

  

    
Remove into ITEM — O(1)

    
1. If START = NULL, write UNDERFLOW and exit.

    
2. Set ITEM := INFO[START], and delete the first node.

    
3. Exit.

  


  
Two-dimensional array representation

  
One queue per priority number. Row K of QUEUE holds the priority-K elements; FRONT[K] and REAR[K] are its front and rear, and NULL (−1) when the row is empty. In C++ this is an array of Queue objects, pq[K].

  

    
Add ITEM with priority number M — O(1)

    
1. Insert ITEM as the rear element of row M (OVERFLOW if row M is full).

    
2. Exit.

  

  

    
Remove into ITEM — O(P), P = number of priority levels

    
1. Find the smallest K such that FRONT[K] ≠ NULL. If there is none, write UNDERFLOW and exit.

    
2. Delete the front element of row K into ITEM.

    
3. Exit.

  


  
Compare the two

  

  
The array reserves space for every row up front, but adds in O(1). The list uses only what it needs and removes in O(1), but adds in O(n). The list stores a PRN and a LINK with every element.


  
Advantages and disadvantages over a general queue

  
Advantage: urgent elements are served first instead of waiting behind earlier ones. Disadvantages: every element needs a priority; add or remove is no longer O(1) at both ends; low-priority elements can wait indefinitely.
